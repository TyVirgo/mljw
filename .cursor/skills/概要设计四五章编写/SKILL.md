# 模板指定章节编写

> 旧名「概要设计四五章编写」仍可用；**不再限定**文档必须是《系统概要设计说明书》，也**不再写死**只能写第四、五章。  
> 以用户给出的**模板 + 指定章节 + 参数点**为准；**先解析模板目录习惯**，禁止把「概要设计默认四级」硬套到详细设计等其它模板。

编写前 **必须先 Read**：

- `openspec/changes/doc-overview-ch45-playbook/design.md`
- `openspec/changes/doc-overview-ch45-playbook/specs/overview-design-ch45/spec.md`
- `openspec/changes/doc-overview-ch45-playbook/tasks.md`
- 新产品先填或代填：`openspec/changes/doc-overview-ch45-playbook/inputs-template.md`

## 闸门：缺料先提示，等拍板再生成（硬性）

下列任一缺失或含糊时，**只列缺口 + 可选默认方案，等待用户确认**；在此之前 **禁止** 生成/覆盖 Word，也禁止用猜测内容「先交一版」。

| 缺口类型 | 典型表现 | Agent 动作 |
|----------|----------|------------|
| 文档模板 | 未给路径/附件，或打不开 | 索要模板；无法解析则说明无法对齐目录 |
| 目标章节 | 未写章号/章名 | 请用户点名要写哪几章 |
| 功能参数点 | 未给菜单/子能力/字段/操作原文 | 索要参数；不得用空话或对标功能顶替 |
| 对标/内容参考 | 用户说了「按某某产品/某文档写」「对照 XX」但未附路径或正文 | 提示缺参考资料，问：补路径 / 放弃对标仅用参数 / 其它 |
| 模板结构未确认 | 模板有明确目录但与默认「模块划分…」冲突，或解析不到编号习惯 | **先给出拟用目录树**，等用户拍板后再写 |
| 关键内容约定 | 接口 path 规范、是否写类图/流程图、图是否占位等用户提过却未定 | 列出待定项，等确认 |

确认话术宜短：缺什么 → 你建议的默认 →「请拍板：A / B / 补材料」。

## 最小输入（三件套；缺一则走闸门）

1. **文档模板**（路径或附件）  
2. **要写哪几章**（章号 + 章标题）  
3. **功能参数点**（菜单/子能力/字段/操作）  

可选：对标产品文档（只学真实文风，不扩功能）。**用户点名要对标却未提供时，按上表闸门处理，不视为可跳过。**

## 硬性规则

1. **只写用户点名的章节**；未点名的章不生成、不灌空壳目录。  
2. **结构优先级**：用户本次指定 > 所给模板该章真实目录 > 下方「概要类默认」。  
3. **概要类默认**（仅当模板/用户未另定功能结构时）：每个菜单下  
   - `…1 模块划分`  
   - `…2 功能列表`  
   - `…3 功能详细描述`（业务子项只做 `…3.n`，序号连续）  
4. **详细设计类（第三章对齐 TOC；第四章接口明细对齐模板正文「用户接口设计」树）**：  
   - 第三章常见：程序描述、模块架构图、功能（概要）、类图、功能（详细，子功能直接 `x.y.z.n`）、程序流程、测试和限制条件——**不要**在 3.5 再套「模块划分/功能列表/功能详细描述」。  
   - 第四章**接口明细主体**须与模板正文一致（用户确认的「用户接口设计」导航树）：  
     `用户接口设计` → `4.1 用户接口` → `4.1.n <菜单/模块>` → `4.1.n.m <接口名>`（含地址/方式/示例/参数表）。  
   - 接口明细之后仍写模板后半的 **全局变量、公用界面或接口、公用方法和过程**（登录界面/登录接口等放此处）；**禁止**把业务模块 API 塞进「4.2 公用界面或接口」冒充主体。  
   - 若模板目录（TOC）写成 4.1 全局变量而正文为 4.1 用户接口：**接口明细以正文「用户接口设计」树为准**（与用户图示一致）。  
   - **不要**默认改成概要式「模块名|接口名称|接口path」三列表（除非用户/模板如此要求）。  
5. **数据库设计类（模板为《数据库设计说明书》时；禁止套概要四级或详细设计接口树）**：  
   - 第四章常见标题：**逻辑设计**——总体实体说明 + E-R/关系图（图题）+ 按模块写详细 ER 说明。  
   - 第五章常见标题：**物理设计和视图设计**——`5.1 / 5.2 / … <模块>设计`（其下 `5.n.m 表中文名（t_xxx）` + 字段表：字段名称/类型/备注/是否可以为空），**最后一节为视图设计**（含具体视图小节，不得只写一句「无视图」空壳除非用户确认）。  
   - 只展开参数点对应模块；表/字段须能追溯到参数操作与属性。  
6. **内容真实**：操作与字段覆盖参数点；不编造清单外能力。  
7. **去 AI 腔**：禁止赋能/闭环/一站式/全方位/底座/沉淀/旨在/致力于等空话；禁止整段粘贴「需支持…」；句式贴近对标真实文档。  
8. 功能列表表头（仅当采用概要类默认且含功能列表时）：一级功能 / 二级功能 / 功能点 / 功能描述。  
9. 样式优先对齐所给模板；解析不到再用黑体标题 + 仿宋正文 + 宋体表。  
10. **优先覆盖未占用文件**；占用则新文件名并告知路径。新产品单独成稿，不覆盖其它产品文档。  
11. 成稿前抽检：目录对齐当前文档类型模板；详设第四章可见「用户接口设计 / 4.1 用户接口」；库设第五章含模块物理表节 + 视图设计节。

## 执行步骤

1. 核对三件套 + 用户是否点名参考资料；走闸门则**停**，等拍板。  
2. 解析模板目标章目录；复杂或与默认冲突时，先贴目录树给用户确认。  
3. 映射菜单与子能力；再生成/覆盖 Word。  
4. 抽检：章节范围、目录与模板一致、序号、无「需支持」堆砌、无 AI 套话。  
5. 回复最终路径 + 本次章节/菜单结构摘要。

## 非目标

- 不写业务代码  
- 不擅自增加参数外功能  
- 不默认生成未指定章节的空壳（除非用户要求预留）  
- 不在缺模板结构确认或缺用户点名的参考资料时「先出一版再说」
