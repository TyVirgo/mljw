# 设计说明：按模板填充指定章节

## 上下文

用户每次提供：

1. **文档模板**（doc/docx，不限定文档类型名称）
2. **要写的章节**（如「第四章、第五章」或「第3章」；以用户声明为准）
3. **功能参数点**（菜单/子功能/字段/操作）
4. **对标参考资料**（可选：同类产品概要/需求/手册，只学写法，不扩范围）

Agent 只填充**被点名的章节**，样式与标题习惯对齐模板；内容边界以参数点为准。

## 决策

### D0 缺料闸门（先拍板再实现）

成稿是**有闸门的动作**：输入不齐或结构未确认时，只澄清、给可选默认，**等待用户拍板**；不得猜测补全后直接写 Word。

| 必停场景 | Agent 行为 |
|----------|------------|
| 缺模板 / 打不开模板 | 索要路径或附件 |
| 缺目标章节（章号+标题） | 请用户点名 |
| 缺功能参数点 | 索要菜单/子能力/字段/操作；禁止用对标产品功能顶替 |
| 用户点名对标/参考文档但未提供 | 提示缺料；选项：补路径、放弃对标仅用参数、改用其它材料 |
| 模板目录与「概要类默认」冲突，或解析不到编号习惯 | 先给出**拟用目录树**，确认后再生成 |
| 用户提过但未定的约定（path 规范、类图/流程图粒度、图占位等） | 列出待定项等确认 |

拍板前禁止：覆盖桌面文件、批量生成「先看一版」、用 AI 套话填空。

### D1 交付范围（通用）

| 决策 | 说明 |
|------|------|
| 只写用户指定的章节 | 未点名的章不生成、不填空壳 |
| 不强制抄全模板目录 | 不为「目录好看」预留未写模块的空标题（除非用户要求预留） |
| 默认可独立成稿 | 可不嵌入原模板全文；标题层级与字体对齐模板 |

**历史常见用法**：指定「第四章模块功能分配 + 第五章接口设计」。这只是一种输入组合，不是唯一绑定。

### D2 结构优先级与功能类标题树

**优先级（高 → 低）**：

1. 用户本次明确指定的目录/标题  
2. **所给模板该章真实目录与编号习惯**（必须先解析）  
3. 下方「概要类默认」（仅回退）

#### D2a 概要类默认（模板未另定时）

当目标章节属于「模块/功能描述」类，且用户与模板均未另行规定结构时，每个写入的功能菜单采用：

```
<章内菜单序号>  <菜单名称>
├── …1 模块划分
├── …2 功能列表
└── …3 功能详细描述
    ├── …3.1 <子能力1>
    ├── …3.2 <子能力2>
    └── …
```

规则：

1. **四级标题名称**（仅在采用本默认时）固定为：模块划分、功能列表、功能详细描述。  
2. 业务子项只出现在「功能详细描述」下的下一级，序号连续。  
3. 序号接在父级后递增，禁止跳跃/异常编号；程序生成时用分段拼接编号。

#### D2b 详细设计类（以模板为准；禁止套 D2a）

若模板为《系统详细设计说明书》一类，常见骨架（**以实际模板 TOC/正文为准，下表仅为防呆**）：

```
第三章 模块设计说明
├── 3.1 程序描述
├── 3.2 模块架构图
├── 3.3 功能          ← 菜单级短述 + 模块划分图/逻辑图题
├── 3.4 类图
│   ├── 3.4.1 程序描述
│   └── 3.4.2 模块架构图
├── 3.5 功能          ← 子功能直接 3.5.x.y，短段能力 + 图题
├── 3.6 程序流程
└── 3.7 测试和限制条件

第四章 公用接口程序说明
├── 用户接口设计                         ← 对齐模板正文导航（用户图示）
│   └── 4.1 用户接口
│       └── 4.1.n 业务模块 → 4.1.n.m 接口明细
│             （接口地址 / 请求方式 / 数据类型 / 描述 / 示例 / 参数表）
├── 全局变量
├── 公用界面或接口                       ← 登录界面/登录接口等
└── 公用方法和过程
```

说明：模板 TOC 可能把 4.1 写成「全局变量」，与正文「4.1 用户接口」冲突。**接口明细主体以正文「用户接口设计」树为准**；不得把业务 API 挂到「4.2 公用界面或接口」下充当主体。

**禁止**：把 D2a 的「模块划分 / 功能列表 / 功能详细描述」写进详细设计 3.5；  
**禁止**：用「仅 TOC 三节」替代「用户接口设计」主体；  
**禁止**：在用户未要求时，把详细设计第四章改成概要式「模块名 | 接口名称 | 接口path」总表替代接口明细。

结构有歧义时走 **D0**：先贴目录树等拍板。

#### D2c 数据库设计类（模板为《数据库设计说明书》时；禁止套 D2a/D2b）

以模板 TOC/正文为准（南海库设类常见）：

```
第四章 逻辑设计
├── 总体说明（涉及实体范围）
├── 图：关系 ER / 实体 E-R / 数据库关系图（图题占位）
└── 详细 ER：按模块（如「系统运维模块」）说明实体及关系

第五章 物理设计和视图设计
├── 5.1 <模块>设计
│   └── 5.1.n 表中文名（t_xxx）+ 字段表（字段名称|类型|备注|是否可以为空）
├── 5.2 …（仅当参数含其它模块时）
└── 5.x 视图设计          ← 模板独立成节；须有具体视图小节，不得空壳敷衍
```

只展开本次参数模块；对标库设资料只学表/字段写法，不扩清单外表。

### D3 接口类章节（若用户指定）

取决于**模板类型**：

| 模板习惯 | 写法 |
|----------|------|
| 概要设计「接口设计」章 | 按菜单拆分；表头默认 **模块名 \| 接口名称 \| 接口path**；path 可占位 |
| 详细设计「公用接口程序说明」 | **正文**：用户接口设计 → 4.1 用户接口 → 4.1.n 模块接口明细；**其后**：全局变量、公用界面或接口、公用方法和过程 |

未要求的接口子节（如内部/外部接口）默认不写。

### D4 文风：去 AI 腔、内容真实

正文必须像真实产品设计文档（可参考对标资料的句子密度与用词），**禁止 AI 套话与假大空**。

| 禁止 | 要求 |
|------|------|
| 「赋能、闭环、一站式、全方位、底座、沉淀、旨在、致力于、从而更好…」等空话 | 直接写：做什么、谁用、维护哪些项、有何约束 |
| 整段粘贴「需支持…」参数原文 | 改写为设计说明语气，但操作/字段不丢 |
| 编造参数未写的指标、架构、收益 | 每句能力都能在参数点或对标资料中找到依据 |
| 过度排比、口号式结尾 | 短句、陈述、可核对 |

推荐每个子能力两段：

1. **作用**：该功能在系统中的位置（1～2 句，具体）  
2. **能力**：可执行操作 + 关键字段/条件 + 约束（删除限制、审核占用、失败次数等）

对标资料用途：学「怎么写」；**标题与能力边界仍以本次参数点为准**。用户点名对标却未给材料 → D0，不得凭印象仿写对标功能集。

### D5 样式

1. **优先**：从用户所给模板抽取标题字体、正文字体、表样式并套用。  
2. **回退**（模板无法解析时）：标题黑体；正文仿宋_GB2312 约 10.5 磅（可首行缩进）；表内宋体约 10.5 磅。  
3. 功能列表表头回退：一级功能 / 二级功能 / 功能点 / 功能描述（仅 D2a）。

### D6 输出与占用

1. 优先覆盖用户指定的未占用目标文件。  
2. 占用则换新文件名并明确告知路径。  
3. 生成后抽检：指定章节是否齐全、**目录是否与已确认的模板结构一致**、序号是否连续、是否残留大段「需支持」与明显 AI 套话。

## 风险与缓解

| 风险 | 缓解 |
|------|------|
| 绑死「概要设计第四五章」 | 输入契约只认「模板 + 章节列表」；D2 优先级 |
| 把概要四级硬套详细设计 | D2b + D0 目录确认 |
| 缺料仍直接出稿 | D0 闸门 |
| AI 腔 | D4 禁用词与抽检；对照对标资料句式 |
| 超范围 | 参数点外不写 |
| 序号损坏 | 分段生成编号 + 抽检 |
