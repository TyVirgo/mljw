# 任务清单：按模板填充指定章节

> 每次新产品/新文档执行一遍。

## 0. 准备输入（闸门）

- [ ] 0.1 取得**文档模板**（任意类型，不限定名称）
- [ ] 0.2 确认**要写的章节**（章号 + 章标题，可多章）
- [ ] 0.3 取得**功能参数点**（菜单、子能力、字段、操作）
- [ ] 0.4 若用户点名对标/参考资料：已取得路径或正文，**或**用户确认放弃对标
- [ ] 0.5 填写 `inputs-template.md` 副本（产品名、章节、菜单、输出路径、结构约定）
- [ ] 0.6 **闸门**：0.1～0.4 未齐则只提示缺口并等待拍板，**不生成 Word**

## 1. 解析模板与落结构

- [ ] 1.1 只规划用户指定的章节（其他章不写）
- [ ] 1.2 从模板确认该章**真实目录**、标题编号习惯与字体（能解析则对齐）
- [ ] 1.3 判定文档类型习惯：概要类默认 vs 详细设计等模板骨架（见 design D2）
- [ ] 1.4 若与默认冲突或解析不清：先贴**拟用目录树**，用户确认后再继续
- [ ] 1.5 参数点映射为功能菜单；仅当模板未另定时才用：模块划分 / 功能列表 / 功能详细描述
- [ ] 1.6 业务子能力按已确认结构挂接，序号连续（详细设计常见为 `3.5.x.y` 直接挂子功能）
- [ ] 1.7 若含详细设计第四章：主体为「用户接口设计 → 4.1 用户接口 → 4.1.n」；其后为全局变量 / 公用界面或接口 / 公用方法和过程；禁止把业务 API 挂在 4.2
- [ ] 1.8 成稿前对照模板正文「用户接口设计」导航树抽检一次

## 2. 正文

- [ ] 2.1 章首/程序描述：用产品域真实表述说明本次写入范围
- [ ] 2.2 若含功能列表：用表格摘要（仅概要类默认）
- [ ] 2.3 子能力：作用 + 具体能力；覆盖参数字段/操作；不整段粘贴「需支持」
- [ ] 2.4 去 AI 腔抽检（无赋能/闭环/一站式等空话；无编造能力）
- [ ] 2.5 对标资料只补表述，不扩参数外功能

## 3. 生成与校验

- [ ] 3.1 样式对齐模板（或回退黑体/仿宋/宋体）
- [ ] 3.2 优先覆盖未占用文件；占用则新文件名
- [ ] 3.3 抽检导航：**与已确认模板目录一致**、指定章节齐全、序号连续、业务子项未占错层级
- [ ] 3.4 抽检：无大段参数原文、无 AI 套话、关键约束仍在
- [ ] 3.5 抽检：未误把概要四级套进详细设计 3.5；第四章可见「用户接口设计 / 4.1 用户接口 / 4.1.n」，业务 API 不在 4.2 下
- [ ] 3.6 抽检：其后含全局变量、公用界面或接口（登录）、公用方法和过程

## 4. 交付

- [ ] 4.1 告知最终文件路径与本次章节/菜单结构摘要
- [ ] 4.2 （可选）归档 `runs/<产品简称>/inputs.md`
