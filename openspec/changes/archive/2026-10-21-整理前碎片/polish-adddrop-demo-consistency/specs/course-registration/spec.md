# 规格：course-registration（delta）

## ADDED Requirements

### Requirement: 加退课列表演示数据不含 Replace

学生加退课/重修申请列表与共享审批队列的演示数据 必须NOT 包含类型为 `Replace` 的申请单。本期可演示的申请类型 必须 仅为 Add、Drop、Retake、AddDrop。

#### Scenario: 学生列表无替换类型

- **WHEN** 演示学生打开「加退课/重修申请」列表
- **THEN** 任意行的申请类型 必须NOT 显示为「替换」/Replace
- **AND** 筛选「申请类型」可选值与可发起类型一致（无 Replace）

#### Scenario: 换课故事用加退关联表达

- **WHEN** 需要演示先退课后加课
- **THEN** 使用类型 `AddDrop`，申请内容含退课与加课两项

### Requirement: 学生端申请课程摘要使用本地化类型文案

学生加退课列表「申请课程」列 必须 使用与审批端一致的申请动作文案（经 i18n 的加课/退课/重修），必须NOT 直接展示英文枚举值 `Add`/`Drop`/`Retake`。

#### Scenario: 中文界面课程摘要

- **WHEN** 界面语言为中文且存在加课申请
- **THEN** 申请课程列显示类似「加课 STAT201」，而非「Add STAT201」

### Requirement: 演示申请的费用与账单状态一致

演示数据中，若申请明细含 `fee > 0`，则该单的 `billStatus` 必须 为 `pending` 或 `paid`（或业务上明确的已取消），必须NOT 在仍有应付费用时为 `none`。重修类演示 必须 至少包含一条待缴费（`pending`）样本。

#### Scenario: 有费加课显示待付款口径

- **WHEN** 管理端待审批列表存在加课且 `fee > 0` 的演示单
- **THEN** 账单列 必须NOT 显示为「—」（none）

#### Scenario: 重修待缴费样本存在

- **WHEN** 查看加退课审批或学生申请演示数据中的重修单
- **THEN** 至少一条重修单账单为待付款且金额大于 0

### Requirement: 演示学分与超限样本克制

同一演示学生的多条待审批申请 必须NOT 全部使用同一超限学分（如均 29/20）。超限学分样本 必须 限制为少量（建议不超过两条）加课或加退关联单；其余申请 必须 使用不超过学分上限的当前学分。

#### Scenario: 待审批不全是超限

- **WHEN** 管理员打开「加退课/重修审批」待审批且列表含演示学生多条记录
- **THEN** 学分列出现超限（当前 > 上限）的行数 必须 少于该生待审批总行数
- **AND** 至少存在一条学分未超限的待审批记录（若该生有多条）

### Requirement: 演示提交时间与申请窗口时间线一致

加退课演示申请的 `submittedAt` 必须 落在当前用于展示的活动批次 `addDropWindow` 日期范围内（按日比较即可），且同一列表内日期时间格式 必须 统一为 `YYYY-MM-DD HH:mm`。

#### Scenario: 开放窗口下提交时间可读

- **WHEN** 页面提示加退课窗口为某起止日期且窗口开放
- **THEN** 列表中演示单的提交日期 必须 落在该起止范围内
- **AND** 提交时间字符串格式一致，必须NOT 混用 `DD-Mon-YYYY` 与 `YYYY-MM-DD`

### Requirement: 含退课的演示申请须有退课原因

演示数据中类型为 `Drop`、`AddDrop` 或 `RetakeDrop`（或明细含退课行）的申请，必须 提供非空的 `dropReason`（可与 `reason` 同步）。申请/审批详情的「退课原因」必须NOT 显示为空白或「—」。

#### Scenario: 加退关联详情可见退课原因

- **WHEN** 打开含退课行的演示申请详情
- **THEN** 「退课原因」字段显示可读说明文字，而非「—」

### Requirement: 毕业超出计费与预估费用一致

演示与 enrich 后的申请中，若毕业超出（计费）学分（`billableCredits` / `feeEstimate.billableCredits`）大于 0，则预估费用（`feeEstimate.total` 或等价应付）必须 大于 0，且与计费学分 × 单价口径一致。必须NOT 出现「毕业超出（计费）> 0 且预估费用为 0」的演示状态。学期超出学分仍允许大于 0 且费用为 0。

#### Scenario: 毕业计费有费

- **WHEN** 审批详情显示「毕业超出学分 (计费)」为 2
- **THEN** 「预估费用」必须 为对应非零金额（含本地生 SST=0 的情况）

### Requirement: 重修演示申请须有合法重修类型

演示数据中类型为 `Retake` 或 `RetakeDrop` 的申请，必须 提供合法的 `retakeType`（`failed` 或 `improve_grade`）。申请/审批详情的「重修类型」必须NOT 显示为空白或「—」。

#### Scenario: 重修详情可见类型

- **WHEN** 打开含重修行的演示申请详情
- **THEN** 「重修类型」显示「不及格重修」或「提升成绩」（或等价英译文案）

### Requirement: 详情学分条与毕业计费一致

演示申请详情中的学分要求条 MUST 表示在原有已选基础上先退后加（或重修）后的最终投影。若「毕业超出学分（计费）」大于 0，则学分条上对应毕业 GE/ME 已选 MUST 大于其要求；MUST NOT 出现条上毕业未超而计费超出大于 0。

#### Scenario: 加退关联真超额

- **WHEN** 打开毕业计费为 2 的加退关联演示详情（如 ADR2509001）
- **THEN** 学分条 ME（或 GE）毕业已选大于要求，且差额与计费学分配套
- **AND** 预估费用与该计费学分一致
