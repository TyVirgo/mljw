## 新增需求

### 需求：学生端学术情况两级展示

系统 MUST 在学生端选课菜单提供「学术情况」（Study Plan）。进入后 MUST 先展示按课程类别的学术情况汇总表（已完成 / 未修·因修 Pending）。汇总表 MUST 含「详情」列；点击后 MUST 进入按学年与学期展开的课程明细表，并可返回汇总。

汇总表中必修课、公共选修（GE）、专业选修（ME）的未修（Pending）学分 MUST 与加退课申请「截止到当前学期落下未修」基线同源，且 MUST 在打开本页时固定，MUST NOT 随其它页面的拟加/拟退勾选变化。其余课程类别与汇总统计列若本系统无模型，MAY 使用 demo 数据填满表格；此类 demo 学分 MUST 控制在与申请侧学分条/培养方案同量级（单列完成与 Pending 宜为个位数或低十位数，MUST NOT 使用如专业核心 Pending 44、最低学分 150 这类虚高刻度）。培养方案最低学分 SHOULD 取培养方案必修+GE+ME 要求之和。课程名称与课号展示 MUST 与课库/申请侧描述一致。中文界面 MUST 使用中文表头与行名。

#### 场景：进入学术情况见类别汇总

- **当** 学生打开「学术情况」菜单
- **则** 展示类别汇总表，含已完成与未修行，以及详情列

#### 场景：详情进入学年学期明细

- **当** 学生在汇总表点击「详情」
- **则** 展示按学年/学期分组的课程明细，可返回汇总
- **并且** 明细页顶栏 MUST 将「学术情况明细（Study Plan）」与「返回学术情况」置于同一行（标题左对齐、按钮右对齐）
- **并且** 明细页学生信息条（学号、姓名、专业、入学、最新 CGPA、已获学分）MUST 横向单行展示、按内容分配间距，MUST NOT 用省略号缩写字段全文（条外 MAY 横滑）

#### 场景：汇总表 Pending 行名

- **当** 中文界面展示类别汇总表
- **则** Pending 行状态文案 MUST 为「因修未修学分」（英文界面为 Catch-up credits）

#### 场景：未修与申请基线一致

- **当** 申请 tip 显示必修落下 4、GE 4、ME 若干
- **则** 学术情况汇总表对应 Pending 绝对值与之一致（打开时固定）
