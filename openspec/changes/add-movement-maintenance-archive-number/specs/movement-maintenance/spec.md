## 新增需求

### 需求：维护列表文号列

异动维护列表应在 **学号列前一列** 展示文号列。未手动填写文号的已通过记录显示 `NA`。

#### 场景：默认显示 NA
- **当** 用户查看已通过且未设置 `exportArchiveNumber` 的维护记录
- **则** 文号列显示 `NA`

#### 场景：显示已保存文号
- **当** 记录已保存 `exportArchiveNumber`
- **则** 文号列显示该值

### 需求：修改文号行操作

维护列表行操作列最左侧应提供「修改文号」按钮，打开弹窗录入文号。

#### 场景：打开修改文号弹窗
- **当** 用户点击「修改文号」
- **则** 系统打开弹窗，允许输入 1–100 个英文字母或数字

#### 场景：文号格式校验
- **当** 用户输入含非英文字母/数字或超过 100 字符的文号并保存
- **则** 系统提示格式错误且不保存

#### 场景：保存文号
- **当** 用户输入合法文号并保存
- **则** 系统写回 `exportArchiveNumber`，列表文号列更新

## 修改需求

### 需求：PDF 文件名使用手动文号

PDF 与附件导出文件名前缀应使用手动维护的文号，不得在未填文号时自动生成随机归档号。

#### 场景：未填文号导出 PDF
- **当** 记录已通过但未设置文号，用户导出 PDF
- **则** 文件名前缀为 `NA.`

#### 场景：已填文号导出 PDF
- **当** 记录已设置文号，用户导出 PDF
- **则** 文件名前缀为 `{文号}.`（如 `1482. AIT2402110 …`）
