# 加退课审批 · 对齐学籍审批布局

## ADDED Requirements

### Requirement: 待我审批 Tab 语义与角标

加退课审批页的待办 Tab 文案必须与学籍异动审批一致，使用「待我审批」，并在该 Tab 上展示待办数量角标。

#### Scenario: 查看待办 Tab

- **当** 用户打开加退课/重修审批页
- **则** 首个 Tab 显示为「待我审批」且带待办条数角标
- **且** 仍存在「已提交」「历史」Tab

### Requirement: 搜索区字段分栏与单行布局

搜索区必须在同一行展示筛选项与查询/重置；至少包含专业（或专业代码）、申请类型、学号、姓名；筛选项不得因默认桌面宽度把操作按钮挤到无关联的第二业务行（与学籍审批搜索区同构）。

#### Scenario: 按学号姓名筛选

- **当** 用户输入学号或姓名并查询
- **则** 列表仅保留匹配的申请行

### Requirement: 待办批量审批工具栏

在「待我审批」Tab，工具栏必须提供主按钮「审批」与「导出」；「审批」在未勾选或无可批选择时禁用。非待办 Tab 可不显示「审批」按钮。

#### Scenario: 勾选后批量审批

- **当** 用户在待我审批勾选一条或多条并点击「审批」
- **则** 系统给出批量通过/驳回确认交互，确认后选中行状态按决策更新并离开待办列表（或按现有队列规则归入已提交/历史）

#### Scenario: 未勾选时审批禁用

- **当** 待我审批 Tab 无勾选
- **则** 「审批」按钮不可用

### Requirement: 勾选列与行内详情

「待我审批」Tab 表格必须提供勾选列（含本页全选）；各 Tab 行操作统一为「详情」，用于打开申请详情（待办可审、其它只读），不得仅依赖行内「审批」文案作为唯一审批入口。

#### Scenario: 打开详情

- **当** 用户点击某行「详情」
- **则** 打开既有加退课审批详情抽屉；若当前为待我审批则允许审批操作，否则只读
