# 选课管理-学生选课结果与历史 规格（合并）

## 说明

以下为各历史 delta spec 原文按来源拼接并做术语中文化处理。整理正式需求文档时，应按场景重写为「用户故事 / 验收标准」，消除重复与过时条目。

## 来源 `enrich-student-history-batch-retake` / 能力 `course-registration`

## ADDED Requirements

### Requirement: 选课历史展示批次与是否重修
学生端选课历史主表 必须展示批次名称与是否重修列；是否重修 必须以是/否展示。演示数据 必须覆盖重修与非重修样例。

### Requirement: 选课历史表横向滚动与换行
选课历史主表 必须支持左右横向滚动。除批次名称列外，各数据列 必须NOT 换行。批次名称列 必须单行展示，超出 必须以省略号截断，并 必须能通过悬停看到完整名称。

### Requirement: 选课历史操作人展示
操作人列 必须在学生本人选课时展示该学生姓名；必须在管理员代选/添加时展示管理员名称。表头提示文案 必须与此规则一致。

## 来源 `polish-student-waitlist-list` / 能力 `course-registration`

## ADDED Requirements

### Requirement: 学生候补结果列表布局与 demo
系统 必须在学生候补结果页提供标准搜索区（审批状态、课程关键词）与查询/重置；列表 必须分页展示并包含学分、教学分组、名额、顺位、申请时间与状态；demo 必须覆盖多种审批状态且字段不出现占位符「—」。

#### Scenario: 搜索与列表列
- **WHEN** 学生打开候补结果页
- **THEN** 可见状态、课程关键词搜索与查询/重置
- **AND** 表格含学分、教学分组、名额、顺位、申请时间、状态列

#### Scenario: 分页与 demo 数据
- **WHEN** 列表渲染当前学生 demo 候补
- **THEN** 可见分页且至少 8 条记录
- **AND** 涵盖待审批、已批准、已拒绝；顺位与申请时间均为实值

## 来源 `refine-student-my-result-unselect` / 能力 `course-registration`

## ADDED Requirements

### Requirement: 学生选课结果页回显与检索
系统 必须在「我的选课结果」页回显学生在线选课确认后的课程结果，字段与确认结果一致，且 必须NOT 展示选课结果数据中不存在的列。页面 必须提供按课程名称的查询与重置。页面 必须NOT 展示轮次时间条/轮次卡片。页面 必须保留模块说明面板及必要的简短业务说明。

#### Scenario: 无轮次卡片
- **WHEN** 学生打开「我的选课结果」
- **THEN** 不展示 `RoundTimelineBar` 或同等轮次卡片组
- **AND** 仍可见模块说明（ModuleBrief）

#### Scenario: 字段与在线选课确认结果对齐
- **WHEN** 学生已通过在线选课确认一门或多门课
- **THEN** 结果表每一行展示：课程代码、课程名称、学分、分组编号、任课教师、起止周、上课时间、上课地点
- **AND** 列名用语与选课模块一致（教学分组 / 分组编号）
- **AND** 不展示开课学期、操作人、操作 IP 等无对应结果数据的列

#### Scenario: 按课程名称检索
- **WHEN** 学生在搜索区输入课程名称关键字并查询
- **THEN** 表格仅显示名称匹配的已选课程
- **AND** 重置后恢复为全部已选课程

### Requirement: 选课阶段退选
系统 必须区分「退选」与「退课」：退选仅适用于未开课、仍处于选课阶段时，学生对已确认选课结果的自助撤销；退课（开课后 Drop）必须NOT 在本页实现。选课阶段内，结果表操作列 必须提供「退选」；成功后 必须从个人选课结果中移除该课并释放对应教学分组名额（原型 mock）。

#### Scenario: 选课阶段退选释放名额
- **WHEN** 当前处于选课阶段且学生对其一门已确认课程点击「退选」并确认
- **THEN** 该课程从「我的选课结果」列表消失
- **AND** 对应教学分组已选人数相应减少（有容量数据时）
- **AND** 不进入加退课审批队列

#### Scenario: 非选课阶段不可退选
- **WHEN** 当前不处于选课阶段（已开课）
- **THEN** 「退选」不可用（隐藏或禁用）
- **AND** 界面提示退课请前往加退课办理（不在本页提交 Drop）

#### Scenario: 退选与退课语义分离
- **WHEN** 学生阅读结果页说明或操作区
- **THEN** 文案将「退选」表述为选课阶段撤销已选
- **AND** 不将「退选」称为开课后的「退课」

### Requirement: 选课结果演示列表与分页
系统 必须在演示环境为学生「我的选课结果」提供足够条数的已确认课程种子数据，以覆盖常见回显形态，并 必须对过滤后的列表提供分页。

#### Scenario: 演示数据覆盖多种回显形态
- **WHEN** 演示环境完成学生选课 demo 种子初始化
- **THEN** 「我的选课结果」展示已确认半池课程（不少于 5 门）
- **AND** 种子中同时包含 ME 与 GE、不同学分、分组编号非仅 01、以及个别缺省排课字段的行

#### Scenario: 结果表分页
- **WHEN** 过滤后的已选课程数大于当前每页条数
- **THEN** 表格仅展示当前页行，并提供分页控件
- **AND** 执行查询或重置后页码回到第 1 页

#### Scenario: 在线选课与结果页对半可操作
- **WHEN** 演示学生打开「在线选课」与「我的选课结果」
- **THEN** 结果页存在多门已确认课程且可选阶段可退选
- **AND** 在线选课列表中约有一半课程资格为可选且有余量（可立即选课/加入选课篮）
- **AND** 列表中仍可见少量不可选或满员候补样例

## 来源 `remove-student-my-schedule` / 能力 `course-registration`

## MODIFIED Requirements

### Requirement: 学生端菜单与页面
系统 必须在选课管理侧栏学生组提供四个入口：在线选课、加退课/重修、我的候补、我的选课结果。系统 必须NOT 提供「我的课表」侧栏菜单或独立学生课表页（`crs-schedule`）。

#### Scenario: 学生侧栏四项
- **WHEN** 用户打开选课管理且查看学生端菜单组
- **THEN** 可见在线选课、加退课/重修、我的候补、我的选课结果
- **AND** 不出现「我的课表」

#### Scenario: 选课队列成功 CTA 进入结果页
- **WHEN** 学生选课队列处理成功并展示成功灯箱
- **THEN** 主操作按钮文案为查看选课结果（或英文等价）
- **AND** 点击后关闭灯箱并进入「我的选课结果」页（`crs-result`）

### Requirement: 学生端教学分组排课字段
系统必须在学生选课相关界面展示教学分组的任课教师、起止周、上课时间、上课地点，并对易混淆字段提供说明。

#### Scenario: 教学分组卡片四字段
- **当** 学生在课程详情选择教学分组
- **则** 每个教学分组卡片展示任课教师、起止周、上课时间、上课地点
- **且** 起止周与上课时间旁提供 ⓘ 字段说明（区分开课周与课时周）

#### Scenario: 选课结果与选课篮同步
- **当** 学生查看选课篮或我的选课结果
- **则** 同步展示上述排课四字段（主在线选课课程列表不增加四列）

## REMOVED Requirements

### Requirement: 我的课表去统计卡（Phase 28）
**Reason**：产品移除学生「我的课表」独立页，相关布局约束不再适用。  
**Migration**：删除 `StudentScheduleView` 与侧栏入口；周课表能力仅保留在管理端监控详情等仍引用 `WeekScheduleGrid` 的位置。

### Requirement: 学生页去掉轮次条（Phase 29）中「我的课表」部分
**Reason**：页面已删除。  
**Migration**：无需迁移；加退课等其余学生页的轮次条规则保持既有实现不变。

## 来源 `remove-waitlist-enrich-history-search` / 能力 `course-registration`

## ADDED Requirements

### Requirement: 学生端不提供候补结果菜单
学生选课菜单 必须NOT 包含「候补结果」入口。

### Requirement: 选课历史支持多字段搜索
选课历史查询区 必须支持按学分、课程分组、任课教师、起止周、上课时间、上课地点、选课时间筛选（可与课程名称组合）。

### Requirement: 可选学生名单精简搜索
按参与范围打开的可选学生名单搜索区 必须NOT 包含批次与所属学院筛选项。

## 增量 `history-academic-session-freeze` / 能力 `course-registration`

## ADDED Requirements

### Requirement: 选课历史展示学年学期
学生端选课历史主表 必须在课程名称列之后展示「学年学期」列。行数据 必须优先取课程上的学年学期，否则回退到所属批次的学年学期。

#### Scenario: 表中可见学年学期
- **WHEN** 学生打开选课历史且存在已确认课程
- **THEN** 每行在课程名称后显示学年学期（无则「—」）

### Requirement: 选课历史可按学年学期搜索
选课历史查询区 必须提供学年学期下拉筛选，选项来自当前历史行去重；与其它条件组合为且AND关系。

#### Scenario: 按学年学期过滤
- **WHEN** 学生选择某一学年学期并查询
- **THEN** 列表仅显示该学年学期的历史行

### Requirement: 选课历史左三列冻结
选课历史主表在横向滚动时 必须冻结序号、课程代码、课程名称三列，使其保持可见。

#### Scenario: 横滑时前三列固定
- **WHEN** 用户在选课历史表上左右横向滚动
- **THEN** 序号、课程代码、课程名称列保持固定，其余列随滚动移动

## 来源 `rename-result-waitlist-add-selected-at` / 能力 `course-registration`

## ADDED Requirements

### Requirement: 学生端结果与候补菜单命名
系统 必须将学生端菜单「我的选课结果」显示为「选课结果」，将「我的候补」显示为「候补结果」。

#### Scenario: 侧栏菜单文案
- **WHEN** 用户打开选课管理并查看学生选课分组菜单
- **THEN** 可见「选课结果」与「候补结果」菜单项（而非「我的选课结果」「我的候补」）

### Requirement: 选课结果展示选课时间
系统 必须在学生选课结果列表中展示每门已选课程的「选课时间」，表示该课在线选课提交成功的时刻；格式 必须为 `YYYY-MM-DD HH:mm:ss`。选课时间 必须NOT 与上课时间混淆。

#### Scenario: 结果表含选课时间列
- **WHEN** 学生打开选课结果页且存在已确认课程
- **THEN** 表格在操作列之前显示「选课时间」列
- **AND** 单元格为 `YYYY-MM-DD HH:mm:ss` 形态（或「—」当无数据）
- **AND** 上课时间列仍单独展示课表时段

#### Scenario: 新提交写入选课时间
- **WHEN** 学生通过在线选课确认提交成功并写入已选结果
- **THEN** 新确认课程带有选课时间戳

## 来源 `rename-section-code-to-group-name` / 能力 `course-registration`

## MODIFIED Requirements

### Requirement: 教学分组展示为分组名称
系统 必须将教学分组标识字段展示为「分组名称」（非「分组编号」）；在线选课分组卡片、候补结果与选课结果列表列名 必须一致；单元格与卡片标题 必须展示完整分组名称（如「分组名称01」），而非仅 code（如「01」）。

#### Scenario: 选课弹层与结果列
- **WHEN** 学生在在线选课中查看教学分组卡片
- **THEN** 卡片标题为完整分组名称（如「分组名称01」）
- **WHEN** 学生查看候补结果或选课结果
- **THEN** 对应列名为「分组名称」，单元格为完整分组名称（如「分组名称01」）
