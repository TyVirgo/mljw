## 新增需求

### 需求：学生维主表与详情

系统 MUST 在学生维主表展示课程来源、操作人、操作时间、原因与选课结果；MUST NOT 在主表展示选课志愿；详情 MUST 仍可查看志愿、原因与附件。

#### 场景：打开学生维

- **当** 用户进入选课结果学生维度
- **则** 主表含原因列且无选课志愿列

### 需求：ME 老生名额使用

ME 批课程维点击老生容量时，系统 MUST 展示各层次配置名额、已分配与剩余可选。弹窗顶部「老生名额合计 / 已分配合计 / 剩余可选合计」MUST 分别与入口行的老生容量总量、已选老生、老生容量可选一致；各层次明细可演示分配，但其剩余可选之和 MUST 等于入口可选数。

#### 场景：查看使用情况

- **当** 用户点击 ME 老生容量数字
- **则** 弹窗按层次列出配置/已分配/剩余可选

#### 场景：入口可选为 53

- **当** 入口「老生容量可选」为 53（或带分母时分子为 53）
- **则** 弹窗「剩余可选合计」为 53，层次剩余加总为 53

### 需求：第二轮新老生容量可选/总量

第二轮课程维 MUST 将新生容量、老生容量表头展示为「…（可选/总量）」，单元格 MUST 为「可选/总量」；分母 MUST 为课级新生/老生容量。第三轮（互释）MUST 仍仅展示可选分子，MUST NOT 展示分母。不扩充时新老容量之和 MUST 等于有效最大总量。

#### 场景：第二轮展示分母

- **当** 用户查看第二轮且某课新生可选 2、新生容量 5、老生可选 53、老生容量 55
- **则** 新生列显示 `2/5`，老生列显示 `53/55`，表头含（可选/总量）

#### 场景：第三轮无分母

- **当** 用户查看第三轮同一课
- **则** 新生列显示 `2`、老生列显示 `53`，表头为「…可选」且无（可选/总量）后缀
