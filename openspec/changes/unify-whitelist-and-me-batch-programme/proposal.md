# 变更：unify-whitelist-and-me-batch-programme

## Why

8.6 老师会议明确：突破常规限制应统一走「白名单」；窗外加退（原补注册）、先修破例加课、学分例外等不应拆成多个菜单。同时 ME 批次需按专业拆分管理权限与开课同步，GE 保持全校一条。现原型菜单仍为「补注册」、白名单页已撤出侧栏，批次表单对 ME 缺少必选专业字段；时效多为整行 24h，不够灵活。

## What Changes

### 白名单（统一突破入口）

- 侧栏菜单名称改为 **白名单**（替换或吞并现「补注册」菜单项；不新增多余菜单）。
- 白名单行按 **权限多选** 配置能力，至少包括：
  - **补注册 / 窗外申请**：窗外可发起**正常**加退课/重修申请流程；
  - **加课 / 退课 / 重修**（可与补注册组合）；
  - **先修豁免**：仅服务白名单加课场景（如末学期来不及读先修）；
  - （可选）突破学分上下限等既有例外类型。
- **白名单只解决「能不能交表」**：批不批、有没有名额、要不要缴费，仍走加退课审批与后续缴费链。
- **加课申请不得突破课程原有容量**（含分组容量）；无余量则不可选该组或申请被校验拦截。
- **在线选课**仍正常校验先修；学生选不了时由教务加入白名单（勾选先修豁免等），再走 **加课申请** 破例，不在三轮选课里静默关掉先修。
- **时效按权限拆分**：每个权限默认 24 小时，可单独改（例如窗外申请 24h，先修豁免可设到学期末）；支持发送邀请 / 再次开放（沿用既有补注册邀请语义，落到对应权限）。

### 批次：ME 必选专业，GE 不变

- 批次类型为 **GE（公共选修）**：保持现有形态（全校统一批次，专业限制仍在课程层）。
- 批次类型为 **ME（专业选修）**：新建/编辑时 **必选所属专业** 字段；列表与详情可展示该专业；后续同步课/名单/权限以该专业为锚（原型 mock 即可）。

## Non-goals

- 不对接真实财务支付闭环（缴费仍可保留过渡说明）。
- 不在本期重做开课自动同步全链路（可预留「按专业同步」说明；课程仍可用隐藏/是否可选）。
- 不把白名单变成「自动审批通过」或「突破容量」。
- 不在在线选课三轮中因白名单而全局关闭先修校验。
- 不新增「白名单中心 + 补注册」双菜单并存。

## 已确认决策

| 议题 | 结论 |
|------|------|
| 菜单名 | 白名单 |
| 补注册 | 作为白名单权限之一，不单独占菜单 |
| 窗外行为 | 有申请类权限 → 窗外走**正常申请流程** |
| 白名单边界 | 只开门交表；审批 / 容量 / 缴费另走 |
| 容量 | 加课申请也不可超原课程/分组容量 |
| 先修 | 在线选课正常验；破例仅白名单加课申请 |
| 时效 | **按权限分时效**；默认每权限 24h，可特殊设置 |
| ME 批次 | 类型 ME 时必选专业；GE 不增该字段 |

## Capabilities

### Modified Capabilities

- `course-registration`：白名单统一模型、加退窗外闸门、先修破例路径、ME 批次专业字段

## Impact

- 菜单：`courseRegistrationMenu.js`、i18n（补注册 → 白名单）
- 管理：原补注册页 / 白名单页合并为白名单列表与表单；监控「建议加入」文案
- 学生：`StudentAddDropView` 窗外闸门读白名单权限与分权限时效；加课选组容量校验；先修豁免仅申请路径
- 批次：`RegistrationBatchFormDrawer`、`registrationBatches.js`（ME.`programme`）
- 数据：`supplementListQueue` 升级或迁入 `whitelistQueue`；加退访问判定
