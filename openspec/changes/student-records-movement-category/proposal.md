# 学籍管理-异动类别配置

> 本变更包由同菜单下多个历史 OpenSpec 变更合并而成，供后续整理需求文档使用。实现状态以原型代码为准；本包作为需求沉淀，不重复驱动增量开发。

## 背景与动机

异动类别配置定义各类学籍异动的实施行为（是否改学籍状态/类型、自动或手动实施）及原因下拉选项，并接入审批 → 维护实施流水线。历史迭代扩展实施开关、优化表单交互并收敛原因可见范围配置。本包按配置与原因管理重组，便于写需求文档。

## 能力范围（按逻辑分组）

### 1. 异动类别与实施行为

- 异动类别列表/表单/原因 CRUD；新增类别弹框扩展三个 **实施行为开关**，接入审批通过后自动实施或进入维护页手动实施。
- 开关控制是否修改学籍状态/类型；「处理选课」区移除第三项「已获得成绩课程不预置到新专业批次名单」（`excludeGradedFromPreset`）。

### 2. 类别表单交互优化

- 三个实施开关的功能说明改为标签旁问号气泡（非灰色常驻文字）。
- 开关 **开启** 时才展示对应「学籍状态 / 学籍类型」下拉并允许选择；开关 **关闭** 时隐藏下拉但 **保留已存值**。
- 列表与表单将「类别」统一为「学籍类型」。

### 3. 异动原因可见范围

- 设置异动原因：增加「适用人员类别」配置，去掉「全部」选项，仅保留 **老师 / 学生** 多选，表达双端共用或单端专用。
- 列表列与编辑弹框最终收敛为 **「是否允许学生申请」** 开关（轨道上展示 **是/否**），替代原多选人员类别交互。
