## 新增需求

### 需求：加退课审批

系统 MUST 提供与当前代码一致的「加退课审批」能力。

#### 场景：处理申请

- **当** 用户打开本菜单
- **则** 界面与数据符合现行实现

### 需求：审批弹框行决策与学分门控

单条审批弹框课程表 MUST 含序号列且尽量不左右滑动。顶部学分要求条在弹框内容滚动时 MUST 保持可见（冻结）。打开弹框时，无历史行决策的行 MUST 默认选中「通过」。行决策变更时学分条 MUST 按通过/待定计入、不通过/驳回不计动态更新（决策 key MUST 含申请类型 action，与弹框行 map 一致）。确认门控 MUST 与学生申请硬拦同源：仅当投影后 GE 或 ME 学期已选 **大于「学期要求 + 因修未修」** 时，确认按钮同一行左侧 MUST 提示超过哪一项且确认 MUST 置灰。条上相对学期要求发红（如 7/6）但未超过因修未修合计上限时 MUST NOT 阻断确认。

#### 场景：打开审批弹框

- **当** 审批人打开含多行课程的审批弹框
- **则** 各行默认「通过」，学分条与申请投影一致，学分条滚动时仍钉在顶部

#### 场景：因修未修顶满不拦确认

- **当** 投影后学期 GE 已选为 7、学期要求为 6、因修未修 GE 为 1（或其它使已选 ≤ 要求+因修未修）
- **则** 条上可对学期要求标红，确认 MUST NOT 因超限置灰，左侧 MUST NOT 出超限提示

#### 场景：否决退课导致超有效上限

- **当** 审批人对某退课行选不通过或驳回，且仍通过的加课/重修使 GE/ME 学期已选大于学期要求+因修未修
- **则** 确认左侧出现超限提示，确认按钮置灰

#### 场景：退课不通过即时回升已选

- **当** 老师将某门退课（如必修 MATH101）由通过改为不通过或驳回，且门控 B 未拦截
- **则** 顶部学分要求对应列（必修/GE/ME）学期与毕业已选 MUST 立即加上该课学分（视为未腾出）

#### 场景：多门退课下否个别课仍可见回升

- **当** 申请含多门退课且原基线某桶已选小于该桶拟退学分合计（易触底为 0）
- **则** 系统 MUST 先将基线该桶抬到至少覆盖全部拟退学分；再将其中一门由通过改为不通过时，对应列已选 MUST 仍回升该课学分（MUST NOT 因触底保持不变）

#### 场景：否退超学期+因修仍可选并软提示

- **当** 老师对退课选不通过或驳回，投影后某桶已选大于该桶学期要求与因修未修之和（如必修 14>9+4）
- **则** 该选中 MUST 生效且条上如实显示超限已选；footer 左下角 MUST 提示不同意退课会影响加课和重修；确认/确定按钮 MUST 置灰；因修 tip 与学期要求分母 MUST NOT 因此改变；MUST NOT 仅因该提示而禁选该决策（radio 仍可改选）

### 需求：不同意退课课表冲突门控

对退课行选「不同意」（`rejected`）时，MUST 校验：恢复该课后其上课时段 MUST NOT 与本单仍计入的加课/重修行（决策为通过或待定）冲突。冲突时 footer 左下角 MUST 提示问题描述，且确认/确定 MUST 置灰；radio 仍可改选。仅「不同意」触发；对退课选「驳回」（`update_required`）MUST NOT 触发本门控。

#### 场景：不同意退课与加课时段冲突

- **当** 本单有退课 AI110 与加课 CHEM101 同周五 08–10，老师对 AI110 退课选不同意
- **则** 左下角出现冲突提示，确定置灰；将退课改回通过或将冲突加课改为不通过/驳回后提示消失且可提交

#### 场景：驳回退课不触发课表门控

- **当** 老师对退课选驳回（非不同意）
- **则** MUST NOT 仅因此弹出本课表冲突门控提示

### 需求：操作与评价意见分列

审批弹窗课程表、学生/老师申请详情课程表、重新提交弹窗行表：MUST 将「操作/决策」与「评价意见」分为相邻两列并拉开间距。操作列仅展示通过/不通过/驳回（radio 或胶囊）；评价意见列展示添加/编辑评价意见、意见详情或「—」。审批弹窗操作列内三个 radio MUST 单行排列（MUST NOT 折成两行）。

#### 场景：审批弹窗拆列

- **当** 打开含行决策的审批弹窗（含草稿回显）
- **则** 表头含操作列与评价意见列；评价意见不在操作列内；操作列与评价意见列视觉间距充足；通过/不通过/驳回 radio 同一行

#### 场景：详情拆列

- **当** 打开学生或老师申请详情且展示行决策
- **则** 退课/加课/重修表均为操作列 + 评价意见列，两列之间间距充足

#### 场景：加课或重修不通过即时减少已选

- **当** 老师将某门加课或重修由通过改为不通过或驳回
- **则** 对应课类已选 MUST 立即减去该课学分

### 需求：历史详情行评价意见

审批历史详情中退课/加课/重修课程表评价意见列：有非空 `lineComment` 时 MUST 展示可点的「意见详情」；无评价意见时 MUST 仅显示「—」（不出按钮）。

审批确认提交时，行级评价意见 MUST 为选填：不通过或驳回行意见为空 MUST NOT 阻止提交；有填写则 MUST 写回该行 `lineComment`。

#### 场景：不通过无意见仍可提交

- **当** 老师将某行选为不通过或驳回且未填写评价意见后点确定
- **则** 提交成功，MUST NOT 提示意见必填

#### 场景：查看历史行意见

- **当** 用户打开已审结申请详情且某课行有评价意见
- **则** 评价意见列可点「意见详情」查看全文

#### 场景：无行意见

- **当** 某课行无 `lineComment`
- **则** 评价意见列显示「—」

### 需求：审批列表超出学分与重修学分分列

待审批与历史主表 MUST 在「超出学分」后增加「重修学分」列。「超出学分」MUST 表示加课侧毕业超出计费学分；「重修学分」MUST 表示重修全额计费学分。纯退课等无对应学分时展示 0 或与现列一致的空态。

#### 场景：含加课与重修的申请

- **当** 列表展示同时含加课毕业超出与重修计费的申请
- **则** 两列分别显示对应学分数，互不混加

### 需求：学分要求流水线动态回显

申请提交、待审/审批中、审结（通过/部分通过/拒绝）各环节的学分要求条 MUST 与该环节行决策投影一致：待审无行决策时按申请全量计入；审批弹框与审结后 MUST 仅将通过（及审批中的待定）计入，不通过与驳回不计。历史详情与学生申请详情 MUST 展示同一审结投影。审批确认 MUST 将投影写回申请的 `termCreditStrip`；详情加载 MUST NOT 用忽略行决策的全量 items 覆盖。

#### 场景：部分通过后打开历史详情

- **当** 申请为部分通过且部分课行为不通过
- **则** 学分要求数字与审批人提交时一致，不把不通过课计入学期/毕业已选

#### 场景：学生查看已审结申请

- **当** 学生打开同一申请详情
- **则** 学分要求与评审历史详情一致

### 需求：学生重提后再审行锁定

老师打开学生重新提交后的待审单时：MUST 回显各行上次通过/不通过/待审决策与评价意见及学生调整后的课数据。**仅当**申请审批日志含学生重新提交（`Resubmitted`）时：打开时行决策已是通过（`approved`）或不通过（`rejected`）的行 MUST 置灰锁定——MUST NOT 再改 radio，MUST NOT 再编辑评价意见，批量操作 MUST NOT 改写这些行；仅 `pending`（原驳回重提）可调整，且打开时 MUST 默认选中上次老师操作「驳回」（`update_required`），MUST NOT 一律默认「通过」。老师首次审批取消并存草稿后再开（无 `Resubmitted`）MUST NOT 锁定，全部行仍可改（含草稿写回的通过/不通过）。全新待审同理全可改（无历史时默认通过）。

#### 场景：重提后再审锁定已同意行

- **当** 学生重提后老师打开审批，本单含已通过 MATH101 与待审 COMP220
- **则** MATH101 行 radio 与评价意见不可改；COMP220 可改

#### 场景：重提后再审 pending 默认驳回

- **当** 学生将原驳回行换课为 pending 后老师打开再审
- **则** 该行 radio MUST 默认「驳回」，MUST NOT 默认「通过」

#### 场景：草稿再开不锁定

- **当** 老师首次审批点了部分通过后取消存草稿，再次打开同一待审单
- **则** 所有行 radio 与评价意见仍可改，MUST NOT 因草稿中的通过/不通过而置灰

### 需求：部分通过仅对通过课生成费用账单

通过或部分通过且需生成账单时，`feeEstimate` 与应收金额 MUST 仅基于行决策为通过的加课/重修（及通过退课对毕业剩余的释放）；不通过与驳回的课程 MUST NOT 出现在费用明细或缴费名单/课程缴费待缴行中。整单拒绝 MUST NOT 生成应付账单。生成待缴账单时 MUST 写入生成时间（`billGeneratedAt`），并同步到学生课程缴费待收费展示。

#### 场景：部分通过含不通过重修

- **当** 申请含多门重修且部分行不通过并勾选生成账单
- **则** 账单与缴费行仅含通过的重修/加课费用

### 需求：审批后费用出口金额一致

列表/详情「预估费用」、历史「账单明细」、学生「课程缴费」中该申请整单：课目与金额 MUST 与该申请审批后的 `feeEstimate`（应付课 amount>0）一致。账单明细 MUST 仅展示本申请应付课程，MUST NOT 混入同学生其它申请或演示待缴行。加课应收为 0 的通过行 MUST NOT 出现在账单明细或待缴整单中。

#### 场景：预估 5000 打开账单明细

- **当** 历史行预估费用为重修三门合计 5000 且无加课应付
- **则** 账单明细待缴仅该三门，课程费合计 5000（SST 按整单规则另计）

#### 场景：学生查看同申请待缴整单

- **当** 学生打开课程缴费中该申请整单
- **则** 门数与金额与预估/账单明细一致

### 需求：账单明细与列表交互不得卡死

打开或刷新加退课审批页、点击查询/审批/详情/账单明细时，界面 MUST 保持可交互。`getApplicationBillDetail` MUST NOT 在计算属性或列表渲染中触发缴费行 reconcile 写库。`mergeLiveUnpaidFromApproval` 在待缴课目与金额未变时 MUST NOT 改写 `paymentLines`。

#### 场景：待审列表连续点击详情与审批

- **当** 用户在待审批 Tab 多次点击详情或审批
- **则** 弹层正常打开，页面不卡死

### 需求：账单明细合计与学生缴费三口径一致

历史「账单明细」待缴合计与已缴合计 MUST 展示课程合计、SST合计、应付合计，金额 MUST 与学生课程缴费该申请整单一致（含 SST 计税口径）。

#### 场景：国际生待缴三门课

- **当** 课程费合计 5300 且学生侧 SST 为 318
- **则** 账单明细待缴合计写出课程 5300、SST 318、应付 5618

### 需求：有应付时缴费成功后才落课与改学分

审批通过或部分通过且生成待缴账单时，MUST NOT 立即将通过行写入学生课表或改变二次申请学分基线。缴费成功将 `billStatus` 置为已付款后 MUST 再落课。无应付账单时，审批结束后 MUST 立即落课。

#### 场景：部分通过待缴未付

- **当** 申请部分通过且账单待付款
- **则** 学生课表与二次申请学分条仍为缴费前状态

#### 场景：缴费成功后

- **当** 学生完成该单缴费
- **则** 通过行落入课表，二次申请学分条反映缴费后学分

### 需求：历史列表操作列短文案单行

历史 tab 主表右冻结「操作」列 MUST 收窄占位。多个操作入口 MUST 保持同一行横排，且操作文案 MUST NOT 换行。列表中原「发送邮件提醒」MUST 展示为「发送邮件」；原「重新生成订单」MUST 展示为「生成订单」（英文对应 Send email / Generate order）。弹窗等非列表入口 MAY 保留完整长文案。

#### 场景：历史行含多个操作

- **当** 历史行同时展示详情、账单明细、发送邮件、生成订单、终止申请等入口

#### 场景：已驳回可终止申请（增量 bo）

- **当** 历史 tab 行状态为已驳回
- **则** MUST 提供「终止申请」；确认后申请变为已取消（`Cancelled`），学生不可再重提
- **则** 各入口同一行单行文案，冻结列窄于原先长文案态，主表更易看见

### 需求：审批弹窗冻结、教师列与取消存草稿

审批弹窗学分要求（含蓝 tip）MUST 钉在滚动区上方（上钉下滚），表格与批量操作滚动时 MUST NOT 从学分条区域透出。「任课教师」列 MUST 加宽并减少缩写。点取消时 MUST 相对打开时的行决策/行意见快照做脏检查：无改动直接关窗；有改动 MUST 提示是否存草稿；确认存草稿则写回待审单各行 `lineDecision`/`lineComment` 且状态仍为待审，再次打开 MUST 回显；选择不保存则丢弃本次改动关窗。

### 需求：审批弹窗附件材料

单条审批弹窗 MUST 在课程表下方展示「附件材料」（只读）：有附件可预览/下载，无附件仍展示该节并显示无。节标题 MUST 仅为「附件材料」（MUST NOT 带 SECTION 前缀）。MUST NOT 在审批弹窗内上传或删除附件。

#### 场景：审批弹窗展示学生附件

- **当** 老师打开含附件的待审申请
- **则** 课程表下方可见「附件材料」并可预览/下载

#### 场景：审批弹窗无附件仍展示节

- **当** 老师打开无附件的待审申请
- **则** 课程表下方仍有「附件材料」小节，内容为无

### 需求：审批弹窗课程预览

单条审批弹窗底栏左侧 MUST 提供「课程预览」。预览 MUST 按当前行决策投影：通过与待定计入加/退/重修；不通过与驳回不计。交互与展示 MUST 对齐学生重新提交的课程预览。

#### 场景：审批勾选驱动预览

- **当** 老师将某加课改为不通过后打开课程预览
- **则** 预览中 MUST NOT 出现该加课虚线

#### 场景：课程预览盖过审批弹窗

- **当** 老师在审批弹窗点「课程预览」
- **则** 预览抽屉完整可见，MUST NOT 被审批弹窗遮挡

### 需求：不同意退课冲突跟手

对退课选「不同意」触发的课表冲突提示 MUST 随当前 `lineDecisionsMap` 实时重算。将冲突退课改回「通过」或「驳回」后，红字 MUST 立即消失。计算时 MUST 以弹窗内 live 决策为准，MUST NOT 回落申请 items 上陈旧的 `lineDecision`。

#### 场景：退课改回通过后红字消失

- **当** 因不同意退课出现冲突红字后，老师将该退课改为通过
- **则** 左下冲突提示 MUST 立刻清空，确定按钮按其它门控恢复

#### 场景：锁定退课冲突以加课重修为问题点

- **当** 学生重提后再审，退课「不通过」已锁定，与新换的加课/重修时段冲突
- **则** 左下提示 MUST 以该加课/重修为问题点（点名加课/重修课号），MUST NOT 再写成「不同意退课…后」为主语

### 需求：审批行操作已驳回

审批弹窗行决策 radio 与详情/重提操作列对 `update_required` MUST 展示「已驳回」，与列表终态「已驳回」一致。

#### 场景：审批 radio 为已驳回

- **当** 老师打开审批弹窗看行操作选项
- **则** 第三项文案为「已驳回」而非单独「驳回」

### 需求：审批申请类型三色胶囊

审批弹窗课程表「申请类型」列 MUST 以彩色胶囊区分加课、退课、重修（与详情 `type-add` / `type-drop` / `type-retake` 同源），MUST NOT 为无样式纯文本。

#### 场景：三类行颜色不同

- **当** 待审单含加课、退课、重修行
- **则** 申请类型列分别为蓝、红、黄胶囊

### 需求：审批落课与我的课表同步

无应付账单时，审批通过/部分通过后 MUST 立即将**通过行**的退/加/重修同步到学生「我的课表」（实线样式，不带申请预览虚线）。有应付账单时 MUST 待缴费成功后再落课；待缴期间 MUST NOT 把未生效的加课/重修算进我的课表，已通过退课亦须在落课生效后才从课表移除。部分通过仅同步老师同意的行。整页刷新后 demo 课表 MUST 恢复为申请前默认底图。历史列表「缴费剩余时间」MUST 单行不换行。

#### 场景：审批无改动取消

- **当** 老师打开审批后未改行决策/意见即取消
- **则** 直接关窗，MUST NOT 弹出存草稿确认

#### 场景：审批存草稿后回显

- **当** 老师改了行决策后取消并确认存草稿，再次打开同一待审单
- **则** 行决策与行意见回显为上次草稿

### 需求：行决策依赖门控与详情日志胶囊

点选通过/不通过/驳回时学分条 MUST 即时重算。若将退课改为不通过或驳回会导致仍通过的加课/重修超过学期 GE/ME 要求，则 MUST 禁止该次点选（含批量），并提示老师先将对应加课/重修行改为不通过或驳回；确认提交门控仍拦截超限。加退课详情时间线 MUST NOT 展示行意见汇总 comment 及蓝底；终态徽章 MUST 对齐列表四态——有驳回行用「已驳回」、无驳回终态用「已结束」，MUST NOT 使用「已拒绝」。详情（学生与老师）操作列通过/不通过/驳回 MUST 以彩色胶囊展示。

#### 场景：否退课导致加课超限禁选

- **当** 审批人欲将腾学分的退课改为不通过，而仍通过的加课会使 GE 学期学分超限
- **则** 该次点选不生效，界面提示须先处理加课/重修行

#### 场景：时间线徽章已驳回

- **当** 申请含驳回行且整单已审结
- **则** 审批日志徽章展示「已驳回」，且无汇总 comment 蓝底

### 需求：审批学分条随行决策跟手

审批弹窗顶部学分矩阵 MUST 随每行通过/不通过/驳回即时更新对应类别已选学分（例如否决一门必修退课后，学期/毕业「必修课」已选 MUST 回升该课学分）。投影前 MUST 将行与课库合并补齐 `type`/`sourceType`/学分，MUST NOT 因行上已有不完整 type 而跳过课库导致退/加不计分。门控 B MUST 仅在拟议态仍有计入学分条的加课/重修，且相对上一决策新引入或加重学期 GE/ME 超限时拦截；纯退课或加/重修均已否/驳时 MUST NOT 因否退回升学分而禁选。拦截后操作列选中态 MUST 与未写入的决策 map 一致。蓝底落下 tip MUST 仍固定不随行决策变。

#### 场景：否决必修退课学分回升

- **当** 老师将 MATH101（必修）退课由通过改为不通过
- **则** 学分矩阵「必修课」学期/毕业已选增加该课学分，MUST NOT 整表数字不变

### 需求：一行操作同步对应学分列

审批行决策变更时，学分分桶 MUST 与该行表头「课程类型」统一类别同源：必修课→必修列，GE-*→公共选修列，ME-*→专业选修列。MUST 只同步该列学期/毕业已选（合计列随之推导）。合理操作（否必修退课、否加课、否重修、以及不会使仍通过的加/重修超学期 GE/ME 的否退课）MUST 直接更新学分条且 MUST NOT 弹拦截提示。仅当否退课会导致仍通过的加课/重修超过学期 GE 或 ME 要求时 MUST 提示并禁止该次点选。

#### 场景：否 GE 退课只动公共选修列

- **当** 老师将一门表头为 GE-* 的退课由通过改为不通过，且不会导致加课超限
- **则** 「公共选修课」已选回升该课学分，必修/ME 列 MUST NOT 因该行而变，且 MUST NOT 弹出拦截提示

#### 场景：否加课直接减已选

- **当** 老师将一门加课或重修由通过改为不通过
- **则** 对应课类已选立即减少该课学分，MUST NOT 弹出拦截提示

#### 场景：纯退课单否 GE 退课顶满仍放行

- **当** 申请仅含退课行（或拟议态下无仍计入的加/重修），全退通过后学期 GE 已选已达要求，老师将一门 GE 退课改为不通过或驳回以致 GE 已选回升并超过学期要求
- **则** 该次点选 MUST 生效，公共选修列已选回升该课学分，MUST NOT 因门控 B 拦截；确认门控仅当终态已选大于学期要求+因修未修时才提示

#### 场景：有计入加课时否退仍可禁选

- **当** 同单仍有计入学分条的加课或重修，且将退课改为不通过/驳回会使学期 GE 或 ME 超限
- **则** 该次点选 MUST NOT 生效，并提示须先处理加课/重修行
