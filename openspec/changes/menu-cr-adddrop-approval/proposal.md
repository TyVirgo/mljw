## 为何

管理端审批加退课/重修申请。

## 变更说明

本包为「加退课/重修审批」的**现行整合规格**，以当前前端代码为准；历史碎片已归档。

- 审批列表与明细以现行为准
- **增量（2026-10-27）：** 审批弹框课程表首列加序号且尽量不横滑；顶部学分要求条滚动时冻结；打开弹框行决策默认「通过」；行选不通过/驳回时学分条动态重算；确认按钮同行左侧提示所超学分要求项，违规时确认置灰
- **增量（2026-10-27 b）：** 修复审批学分条决策 key（须含 action）使通过/不通过/驳回真正驱动学期与毕业学分投影；历史详情课程表操作列增加「意见详情」（无 `lineComment` 则显示 —）
- **增量（2026-10-27 c）：** 历史详情操作列始终展示「意见详情」入口（无意见弹层内为 —）；演示种子为部分通过/不通过行写入 `lineComment`，避免看起来像未实现
- **增量（2026-10-27 d）：** 详情「意见详情」仅有评价意见时出按钮，否则「—」；待审批/历史主表在「超出学分」后增「重修学分」列——超出=加课毕业超出计费，重修=重修缴费学分
- **增量（2026-10-28）：** 学分要求按申请→评审→审结流水线动态回显（与行决策同源）；审批提交写回 `termCreditStrip`/`feeEstimate`；历史与学生详情一致；部分通过账单仅含通过且需缴费的加/重修课
- **增量（2026-10-28 b）：** 预估费用、历史「账单明细」、学生课程缴费整单金额与课目 MUST 与审批后 `feeEstimate` 一致；单条账单明细只展示该申请应付课
- **增量（2026-10-28 c）：** 修复账单/缴费 reconcile 在渲染路径反复写 `paymentLines` 导致页面卡死；明细只读预估，merge 仅审批后/进缴费页/显式打开账单且内容有变时写库
- **增量（2026-10-28 d）：** 账单明细待缴/已缴合计与学生缴费三口径一致（课程合计、SST、应付合计）；有应付时选课/学分生效延后到缴费成功
- **增量（操作列布局）：** 历史 tab 右冻结操作列收窄；操作单行不换行；列表文案缩短为「发送邮件」「生成订单」
- **增量（审批弹窗）：** 学分要求改为上钉下滚冻结；任课教师列左移少缩写；取消时有改动才问是否存草稿，存则写回行决策/意见，再次打开回显
- **增量（落课与课表）：** 重申无应付即落课、有应付缴完才落课；我的课表仅同步已生效的通过行；刷新恢复默认课表；缴费剩余时间不换行
- **增量（审批决策门控与详情）：** 行决策实时学分；否退课致加课超限则禁选并提示；日志去汇总 comment、徽章对齐已驳回/已结束；详情操作胶囊
- **增量（学分条跟手修复）：** 审批顶栏学分矩阵 MUST 随行决策即时变数；课类 enrich 与表头同源；门控 B 仅拦「新引入/加重」超限并回滚 radio
- **增量（一行一列）：** 操作单行只同步该行课类对应列；学分分桶与表头统一类别同源；仅不合理操作（否退致加/重修超 GE/ME）提示，合理操作直接变数
- **增量（门控 B 纯退课）：** 纯退课单（或拟议态下无仍计入的加/重修）否/驳退课 MUST 放行并一操作一变化；门控 B MUST NOT 把「否退把选修学分加回去后顶满/超限」当成禁选；仅当仍有计入的加/重修且否退导致其超学期 GE/ME 时才提示拦截
- **增量（评价意见非必填）：** 行级「评价意见」改为选填；不通过/驳回确认提交 MUST NOT 因意见为空而拦截
- **增量（2026-11-11 an）：** 确认门控与门控 B 的「超学期 GE/ME」改与学生申请硬拦同源：有效上限=学期要求+因修未修；仅投影后已选仍大于该合计时才左侧提示并禁确定。条上相对学期要求发红（如 7/6 但因修未修≥1）MUST NOT 单独阻断
- **增量（2026-11-11 ap）：** 加固审批「点选 ↔ 学分条」实时联动：退课不通过/驳回 → 该课学分加回已选；加课/重修不通过/驳回 → 不加进已选；通过则按加/退投影。行操作 radio 受控点击写 map，学分条 MUST 随 map 即时重算（含必修/GE/ME 各列）
- **增量（2026-11-11 aq）：** 修复个别退课否/驳后学分条不动：投影前基线各桶已选 MUST 至少覆盖本单该桶全部拟退学分，避免 `max(0,基线−拟退)` 触底后否个别课仍为 0、看不出回升
- **增量（2026-11-11 ar）：** 否/驳退课后若已选 > 学期要求+因修未修（含必修），仍可选中并条上如实显示（如 14/9）；左下角软提示「不同意退课会影响加课和重修」；因修 tip 与要求分母不变。审批弹窗与详情（学生/老师）操作与评价意见拆为两列
- **增量（2026-11-11 as）：** 保留操作/评价意见两列但拉开间距（审批 radio 单行不折、列宽与列间距加大）；上述软提示一旦出现，确认/确定 MUST 置灰（仍可选中 radio）
- **增量（2026-11-11 av，与 student 对齐）：** 学生重提后再审打开时回显上次行决策与意见及学生调整后课数据；全部行可再改（不锁通过/不通过 radio）；首次待审草稿行为不变
- **增量（2026-11-11 ay，修订 av）：** 再审时打开时已是「通过」或「不通过」的行 MUST 置灰锁定（radio 与评价意见均不可改）；仅原驳回现为 `pending`（及尚无历史终态决策）的行可调整。推翻 av「全部可再改」。审结有应付时账单 MUST 带生成时间并同步进学生课程缴费
- **增量（2026-11-11 az，收窄 ay）：** 行锁定仅适用于**学生驳回后重新提交**再审（`approvalLog` 含 `Resubmitted`）。老师首次审批取消存草稿后再开 MUST NOT 锁定，全部行仍可改
- **增量（2026-11-11 bb）：** 学生重提后再审打开时，原驳回现为 `pending` 的行 MUST 默认回显上次老师操作（驳回 `update_required`），MUST NOT 一律默认「通过」
- **增量（2026-11-11 bd）：** 对退课行选「不同意」（仅 `rejected`，不含驳回）时，MUST 校验恢复该课后时段是否与仍计入的加课/重修冲突；冲突则左下角提示且确定置灰。驳回（`update_required`）退课 MUST NOT 触发本门控
- **增量（2026-11-12 bf）：** 审批弹窗课程表下方 MUST 展示学生「附件材料」（只读预览/下载，空也展示该节）
- **增量（2026-11-12 bg）：** 附件节标题 MUST 仅为「附件材料」（无 SECTION 前缀），排版对齐申请/详情。底栏左侧 MUST 提供「课程预览」，投影随当前行决策（通过/待定计入；不通过/驳回不计），交互对齐学生重提预览
- **增量（2026-11-12 bh）：** 课程预览抽屉 z-index MUST 高于审批弹窗，MUST NOT 被遮蔽。不同意退课课表冲突红字 MUST 随行决策 radio 实时更新；退课改为通过/驳回后 MUST 立刻消失（MUST NOT 回落陈旧 `items.lineDecision`）
- **增量（2026-11-12 bi）：** 审批弹窗课程表「申请类型」列加课/退课/重修 MUST 用不同颜色胶囊区分（与详情 type-add/drop/retake 同源）
- **增量（2026-11-12 bj）：** 行操作「驳回」展示统一为「已驳回」（radio/批量文案与详情胶囊一致）。不同意退课与加课/重修冲突时：若该退课决策已锁定（学生重提后再审），提示 MUST 以加课/重修为问题点；老师当场改「不通过」退课仍可提示退课侧
- **增量（2026-11-12 bo）：** 历史 tab「中止申请」文案统一为「终止申请」。已驳回行 MUST 亦可终止（关闭为 `Cancelled`，学生不可再重提）；已通过且待付款的终止行为不变
