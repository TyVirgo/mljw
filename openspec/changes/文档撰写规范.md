# OpenSpec 变更包中文撰写规范

本仓库 `openspec/changes/` 下所有变更包文档**统一使用简体中文**描述，便于开发人员阅读。下列规范适用于 `proposal.md`、`design.md`、`tasks.md`、`specs/**/*.md`。

## 章节标题对照

| 原英文标题 | 中文标题 |
|-----------|----------|
| Why | 背景与动机 |
| What Changes | 变更内容 |
| Context | 背景说明 |
| Goals / Non-Goals | 目标 / 非目标 |
| Decisions | 设计决策 |
| Capabilities | 能力范围 |
| New Capabilities | 新增能力 |
| Modified Capabilities | 修改的能力 |
| Impact | 影响范围 |
| Non-goals | 非目标（本变更不做） |
| Implementation status | 实现状态 |
| ADDED Requirements | 新增需求 |
| MODIFIED Requirements | 修改需求 |
| REMOVED Requirements | 移除需求 |
| Scenario | 场景 |
| Migration | 迁移说明 |
| Risks | 风险与应对 |

## 保留英文的内容（不翻译）

- 文件路径、组件名、函数名、变量名（如 `MovementApprovalModal.vue`）
- 存库枚举值（如 `Approved`、`Update Required`）
- 能力标识 slug（如 `movement-approval-app`）
- Git 提交号、分支名
- 代码块内的代码

## 语句风格

- 使用完整、通顺的中文句子，避免中英夹杂的标题句（如「Add Export Modal」应写「接入导出弹框」）
- 列表项用动词开头或名词短语，保持一致
- 任务清单（tasks.md）每条用「动词 + 对象 + 结果/验收点」描述
- 需求规格（spec.md）场景用「当…则…」句式，不用 WHEN/THEN 英文

## 示例

**变更内容条目（好）：**

> 在审核弹框的「操作」单选行中，将选项文案统一为：通过、不通过、驳回。

**变更内容条目（差）：**

> Update Action labels to Pass / Not Pass / Return in Approval Modal.
