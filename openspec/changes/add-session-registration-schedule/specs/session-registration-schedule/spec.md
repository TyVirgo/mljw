# 规格：session-registration-schedule

## ADDED Requirements

### Requirement: 选课时间配置菜单与学期列表
系统 必须 在选课管理「批次与规则」下提供「选课时间配置」菜单。主页面 必须 以学年学期为行展示全局配置列表，列 必须 含第一轮/第二轮/第三轮选课时间（新生与老生各一行）、结果公布、加退课/重修申请时间，并提供筛选、新增、删除与「修改」「单位批次时间设置」操作。主表 必须NOT 再展示「老生 R1」单列或「覆盖批次数」。

#### Scenario: 打开菜单见学期列表
- **WHEN** 管理员进入选课时间配置
- **THEN** 看到按学年学期排列的表格，含三轮双受众时间与结果公布、加退课列，可新增或修改某学期全局配置

#### Scenario: 主表不含覆盖计数
- **WHEN** 管理员查看选课时间配置列表
- **THEN** 不可见「覆盖批次数」列；仍可通过操作进入单位批次时间设置

### Requirement: 学期全局配置必填
新建或修改学期全局配置时，系统 必须 要求填写老生三轮时间、结果发布时间、新生三轮时间、加退课申请起止（与学年学期同排展示），以及 GE 衰减系数 r。缺项 必须NOT 保存。时间顺序校验 必须 与既有管理轮次规则一致（老生 R2 起算结果公布）。

#### Scenario: 缺公布时间不能保存
- **WHEN** 管理员清空结果发布时间并保存全局配置
- **THEN** 提示必填且不保存

#### Scenario: 加退课与学期同排
- **WHEN** 管理员打开学期全局编辑抽屉
- **THEN** 加退课/重修申请起止与学年学期在同一行区域展示，且全学期共用一套时间

### Requirement: 单位批次时间可选
在同一学年学期下，系统 必须 允许通过「新增单位」为学院单位配置自定义三轮选课时间（新生与老生）。交互 必须 为：点击按钮 → 多选未配置单位 → 配置时间；已配置单位 必须 置灰不可再选。单位配置 必须 仅含 R1–R3 双受众，必须NOT 含结果公布、衰减 r、ME 名额或加退课。抽屉列表 必须 展示学院单位、第一轮/第二轮/第三轮（双受众）与操作。

#### Scenario: 新增多个单位
- **WHEN** 管理员勾选单位 A、B 并保存相同三轮时间
- **THEN** 列表出现 A、B 两行，各自持有该时间配置

#### Scenario: 单位不含公布与加退课
- **WHEN** 管理员编辑某单位批次时间
- **THEN** 不可见结果公布、衰减系数、ME 名额或加退课字段

#### Scenario: 删除单位配置回退全局
- **WHEN** 管理员删除某单位的时间配置
- **THEN** 该单位所属批次/学生生效轮次改回学期全局

### Requirement: 生效解析
三轮选课时间的生效值 必须 为：存在同学期单位覆盖则用单位配置（结果公布仍取学期全局），否则用学期全局。GE 衰减系数 `decayR` 必须 取学期全局。ME 批次 `round1Quota.meQuotaRows` 与 `totalCap` 必须 取批次自身。加退课申请窗 必须 取学期全局，必须NOT 按单位或批次单独配置。

#### Scenario: 无单位覆盖用全局
- **WHEN** 批次所属学院无单位覆盖且学期全局已配置
- **THEN** 学生端展示的轮次时间等于全局配置（含全局结果公布）

#### Scenario: 加退课读学期
- **WHEN** 学生发起加退课
- **THEN** 是否在申请窗内仅依据该学年学期全局 addDropWindow 判定

### Requirement: 批次管理去掉轮次入口
选课批次列表 必须NOT 再提供「管理轮次」。批次新建/编辑 必须NOT 再配置加退课申请窗与选课轮次时间。批次列表 必须NOT 展示第一轮/第二轮/第三轮或加退课时间列（改在选课时间配置主表查看）。

#### Scenario: 批次操作列
- **WHEN** 管理员查看进行中批次的操作列
- **THEN** 可见管理课程、学生清单等，不可见管理轮次，且列表无轮次时间列

#### Scenario: 批次列表无时间列
- **WHEN** 管理员打开选课批次列表
- **THEN** 表格不含第一轮/第二轮/第三轮/加退课时间列

### Requirement: ME 灵活入学学期占比
ME 批次 `round1Quota` 必须 含 `totalCap`（名额总数）与 `meQuotaRows[]`。每行 `kind` 为 `intake` 或 `special`，含 `share`（%）与 `count`（名额数）；三者 必须 可编辑并联动（改占比→算名额数，改名额数→算占比，改总数→按占比重算名额数）。`intake` 行 必须 可挂多个 `YYYY/MM`（学期仅 02/04/09）。`special` 行 必须 固定存在且置末，文案「特殊学生（包含特殊名单）」，不可删除；必须NOT 提供「+ 特殊学生行」。入学学期行添加按钮文案 必须为「新增」。占比合计 必须 为 100%；名额数合计 必须 等于 `totalCap`。有特殊名单时 special 占比与名额数 必须 > 0。配置入口 必须 在批次表单第 3 节（`type=ME`）；编辑时参与范围为第 4 节。新建批次类型默认「请选择」。抽签仍按 `share` 切分运行时容量；特殊名单优先。

#### Scenario: 一行挂多入学学期
- **WHEN** 管理员在一行添加 `2024/09` 与 `2025/04` 并设占比 40%
- **THEN** 两学期共用该行 40% 名额桶，名额数随 totalCap 联动

#### Scenario: 有特殊名单占比为 0 不能保存
- **WHEN** 批次特殊名单非空且特殊学生行占比或名额数为 0
- **THEN** 提示需分配名额且不保存

#### Scenario: 批次 ME 名额配置节
- **WHEN** 管理员新建或编辑 ME 批次
- **THEN** 见第 3 节名额占比表（含名额总数、占比、名额数）；GE 批次不可见该节

#### Scenario: 特殊学生行不可删
- **WHEN** 管理员在 ME 名额表操作 special 行
- **THEN** 无删除操作；表末始终有一行「特殊学生（包含特殊名单）」
