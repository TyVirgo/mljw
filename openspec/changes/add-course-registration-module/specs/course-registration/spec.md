## 新增需求

### 需求：教学门户选课管理入口

系统必须在教学门户提供「选课管理」应用入口，进入后展示独立侧边栏与内容区，布局风格与学籍管理一致。

#### 场景：教务人员进入选课管理

- **当** 用户在教学门户点击「选课管理」
- **则** 系统切换到选课管理应用，默认展示选课批次列表页

#### 场景：列表页布局与学籍管理一致

- **当** 用户打开选课管理任一列表页（批次、课程、监控、审批等）
- **则** 页面自上而下为：搜索条件区（左上左对齐，查询/重置右上同行）→ 操作工具栏（新建/导出等）→ 数据表格与分页
- **且** 样式复用 `list-page-search.css` 与 `course-registration-list.css`，与学籍管理列表页视觉一致

#### 场景：模块顶部需求说明

- **当** 用户进入任一选课子菜单
- **则** 页面顶部展示调研来源、文档需求要点与本页功能映射，便于开发对照实现

#### 场景：高并发选课队列

- **当** 学生/管理员触发核心选课提交（demo：学生确认选课、监控模拟提交或审批批准加课）
- **则** 以半透明灯箱展示选课队列，含预计等待时间（默认 5–8 秒）与课程信息卡片；处理完成后进入成功/失败后续流程
- **且** 底层页面仍可见（非全屏实色蒙版）

#### 场景：学生端轮次时间轴

- **当** 学生进入在线选课、课表、加退课、候补或结果任一页
- **则** 页面展示 Pre/Main/Supp/Add-Drop 四轮时间轴，并高亮与当前页面相关的轮次阶段

#### 场景：在线选课轮次切换

- **当** 学生在在线选课页点击不同轮次卡片
- **则** 展示对应轮次说明与内容：预选为志愿清单、正选/补选为课程列表与选课篮
- **当** 学生点击 Add/Drop 轮次卡片
- **则** 直接跳转加退课/重修页面，不在在线选课页展示中间说明
- **且** 每轮卡片悬停 tooltip 展示调研规则摘要

---

### 需求：选课批次管理

系统必须支持按学期创建选课批次，配置 ME/GE/Mandatory 注册类型、三轮选课时间、Add/Drop 时间、退课截止、参与 Program+Intake 范围及学分上下限。

#### 场景：创建并发布 ME 批次

- **当** AC 填写批次信息并点击「发布」
- **则** 批次状态变为「进行中」，参与范围内学生可在对应轮次进行选课（原型为 demo 状态变更）

#### 场景：自动纳入复学学生

- **当** 批次勾选「自动导入复学学生」且存在复学标签学生
- **则** 该学生纳入本批次可选范围，不受常规 Intake 筛选限制

#### 场景：从批次管理可选课程

- **当** AC 在批次列表点击「管理课程」或「课程数」
- **则** 打开绑定该批次的课程管理抽屉，标题明示批次名称
- **且** 侧边栏不再提供独立「可选课程」菜单

#### 场景：列表与导出轮次拆列（Phase 20）

- **当** AC 查看选课批次列表
- **则** 展示四列：预选（Pre）、正选（Main）、补选（Supp）、Add/Drop；值为各阶段时间段
- **且** 时间格式与表单日期选择器一致（`DD/MM/YYYY – DD/MM/YYYY`）
- **当** AC 导出批次
- **则** 导出字段选择器包含上述四列并可独立勾选，不提供合并的轮次摘要列
- **且** 导出日期格式与列表一致

---

### 需求：可选课程配置

系统必须在选课批次上下文中为每个批次配置可选课程列表，展示教学分组、容量、新老生配额及选课限制；课程库与排课数据为只读引用。课程管理通过批次页抽屉完成，不设独立菜单页。

#### 场景：从课程库多选导入

- **当** AC 在批次课程抽屉点击「从课程库导入」
- **则** 打开课程选择器（搜索、多选、分页）；已在本批次的课程不可再选
- **当** AC 确认选中课程
- **则** 课程加入当前批次可选列表

#### 场景：配置新老生配额

- **当** AC 设置总容量 50、老生 30、新生 20
- **则** 新生端仅看到新生可用名额；老生未满时可按配置释放给新生

#### 场景：外部数据只读提示

- **当** AC 查看先修课或教室字段
- **则** 字段为只读并显示 tooltip 标明数据来源（培养方案/排课模块）

---

### 需求：学生选课监控

系统必须按 Program+Intake 实时监控学生选课进度，统计学分合规、GE 类别、先修课问题，并支持 AC 干预。

#### 场景：识别学分不足学生

- **当** 长学期学生已选学分低于 12
- **则** 列表标记「学分不足」，统计卡计数 +1，详情抽屉展示问题说明

#### 场景：加入补注册名单

- **当** AC 在监控页点击「加入补注册名单」
- **则** 学生进入补注册名单（Phase 2），并记录操作人与时间

#### 场景：发送提醒

- **当** AC 选择学生并发送提醒
- **则** 系统展示邮件模板预览并记录发送动作（Phase 1 可为模拟 toast）

---

### 需求：加退课与重修审批

系统必须统一处理 Add、Drop、Retake、Replace 及 Add&Drop 关联申请，校验学分上限、时间冲突、先修课，并支持审批与账单状态管理。

#### 场景：关联申请先 Drop 后 Add

- **当** 学生同时申请 Drop COMP201 与 Add COMP3192（Retake F），且存在时间冲突
- **则** 审批详情提示「先批准 Drop 再批准 Add」，审批后学分与时间均合规

#### 场景：Retake F 优先

- **当** 重修席位有限且同时存在 Retake F 与 Retake M 申请
- **则** 审批界面标识 F 类优先，建议先满足 F

#### 场景：生成账单与付款超时

- **当** AC 批准需付费的 Add/Retake 申请
- **则** 生成账单并进入「待付款」状态；超过配置窗口（默认 48 小时）未付款则自动取消并释放名额

#### 场景：审批通过加入上课名单

- **当** 无需付费或已付款的 Add/Retake 审批通过
- **则** 学生出现在对应教学分组上课名单（demo 状态更新）

---

### 需求：三轮选课与学分规则

系统必须支持第一轮预选（随机分配）、第二轮正选（先到先得）、第三轮补选；并强制执行学期学分上下限。

#### 场景：第一轮超额预选

- **当** 第一轮结束选课人数超过容量
- **则** 系统按配置规则筛选入选名单（如高年级优先），未入选者进入第二轮补选

#### 场景：超学分不可直接 Add

- **当** 学生当前学分已达上限且未先 Drop
- **则** 禁止提交 Add 申请或审批界面显示超限拒绝

---

### 需求：G1 类别学分约束

当学生剩余可选 GE 学分不足以满足未完成的类别最低要求时，系统必须限制其继续选择该类别课程并给出提醒。

#### 场景：商科已满仅剩 6 学分且文科未达标

- **当** 学生已修 12 学分商科、文科差 6 学分、剩余仅 6 学分可选
- **则** 禁止再选商科课程，并提示需选文科类别

#### 场景：数学专业例外

- **当** 专业配置为不强制 GE 子类别最低学分
- **则** 仅校验 GE 总学分，不启用子类别限制

---

### 需求：补注册与白名单（Phase 2）

系统必须为错过选课周期或经 BOA 批准的特殊学生提供补注册通道与白名单权限。

#### 场景：补注册突破 Intake 范围

- **当** 复学学生被加入补注册名单
- **则** 可在选课结束后从有余量课程中自助补选（需等主轮次结束）

#### 场景：白名单先修课例外

- **当** 学生经 BOA 批准获得先修课例外白名单
- **则** 加课时可选择 normally 因先修课缺失而不可选的课程

---

### 需求：选课结果与 Study Plan 同步占位（Phase 2）

系统必须展示选课结果并预留与 Study Plan 同步能力；Phase 1 仅模拟同步成功。

#### 场景：一键同步 Study Plan

- **当** AC 点击「一键同步到 Study Plan」
- **则** 显示确认文案「仅同步当学期真实选课，不影响未来学期人工安排」；确认后 toast 成功（原型）

---

### 需求：外部模块数据边界

本模块不得编辑课程库、培养方案、排课、财务真实数据；仅只读展示或 demo 占位。

#### 场景：查看教学分组教室

- **当** AC 在可选课程查看教室
- **则** 显示 demo 教室名与 tooltip「数据由排课模块同步」

---

### 需求：学生选课资格引擎（Phase 6）

系统必须在学生在线选课与加入选课篮时，按批次范围、学籍状态、先修课与已修课程判定可选资格，并给出不可选原因。

#### 场景：先修课缺失拦截

- **当** 学生已修 COMP101 但未修 COMP201，尝试选择 COMP3192（先修 COMP201）
- **则** 列表标记「缺少先修课：COMP201」，选课按钮禁用；若强行提交则 `addToCart` 返回错误

#### 场景：已修课程不可重复选

- **当** 学生本学期已确认选修 COMP101
- **则** COMP101 标记「已修读」，不可再次加入选课篮

#### 场景：批次范围过滤

- **当** 学生 Program+Intake 不在批次 `scope` 内
- **则** 该批次课程均不可选，并提示「不在本批次 Program+Intake 范围」

#### 场景：白名单先修例外（学生端）

- **当** 学生经 BOA 批准获得某课程的先修例外白名单
- **则** 该课程在学生端标记为可选（含白名单豁免提示），可正常加入选课篮

#### 场景：专业限选课程

- **当** 课程配置 `audience.programmes` 仅含 SWE，非 SWE 专业学生查看
- **则** 标记「限指定专业」并禁止选课

---

### 需求：模块流程说明页（Phase 7）

系统必须在选课模块侧边栏提供全局流程说明页，单页自上而下展示学期时间轴、管理端/学生端主流程、两端联动与顺序约束；节点可点击跳转对应原型功能页。

#### 场景：浏览全流程

- **当** 用户打开「流程说明」菜单
- **则** 单页展示 A–K 时间轴、管理端 10 节点、学生端 5 节点、联动关系与 8 条约束摘要

#### 场景：点击节点跳转

- **当** 用户点击流程图中某菜单节点
- **则** 跳转至对应功能页（如 `cr-monitor`、`crs-register`）

#### 场景：时间轴高亮

- **当** 用户点击时间轴某阶段（如「正选/补选 D」）
- **则** 高亮该阶段关联的菜单节点

#### 场景：非业务编排声明

- **当** 用户进入流程说明页
- **则** 页顶展示 rule 级提示：本页为原型说明，不代表系统编排引擎

---

### 需求：批次表单抽屉体验（Phase 8）

系统必须在新建/编辑批次抽屉中展示四步序号表单，学年学期为 `2024/09` 格式下拉，轮次日期使用日期选择器，且草稿保存仅校验步骤 1 必填项。

#### 场景：步骤序号与必填标注

- **当** AC 打开新建批次抽屉
- **则** 展示步骤 1–4 序号标题；仅批次名称、学年学期、类型标为必填

#### 场景：学年学期下拉

- **当** AC 选择学年学期
- **则** 从 `2024/09` 格式选项列表中选择，与学籍/异动模块一致

#### 场景：轮次日期选择器

- **当** AC 配置预选/正选/补选/Add-Drop 日期
- **则** 使用 `DatePickerEn` 组件，选填；未填时轮次摘要为空

#### 场景：草稿最小保存

- **当** AC 仅填写步骤 1 后点击保存
- **则** 批次以草稿状态保存成功；发布时仍校验参与范围

---

### 需求：选课类型 ME/GE/Mandatory（Phase 9）

系统必须使用调研术语 ME（Major Elective）、GE（General Elective）、Mandatory 作为批次与课程类型，并提供类型字段 tooltip 说明。

#### 场景：批次类型 tooltip

- **当** AC 在批次抽屉查看「类型」字段
- **则** 展示三类含义说明：ME 专业选修、GE 公共选修、Mandatory 必修注册

#### 场景：课程类型展示

- **当** 学生在选课列表或 AC 在可选课程详情查看课程类型
- **则** 显示 `ME · 专业选修` 或 `GE · 公共选修`，不再显示 M1/G1

---

### 需求：学生端课程详情与列表优化（Phase 17）

系统必须优化学生在线选课页的课程列表与详情抽屉，减少选课步骤并避免资格信息重复展示。

#### 场景：名额状态合并列

- **当** 学生查看在线选课课程列表
- **则** 以「名额状态」列同时展示余量（如 `12/30`）、满员/开放/已在选课篮状态，不再分列「状态」与「容量」

#### 场景：资格短标签与 tooltip

- **当** 课程不可选
- **则** 资格列仅显示「不可选」短标签；悬停 tooltip 展示完整原因（先修/范围/已修/学籍等）
- **且** 操作列不重复展示资格说明文案

#### 场景：立即选课快捷路径

- **当** 课程可选且仅有一个有余量教学分组
- **则** 点击「立即选课」直接加入选课篮，无需打开详情
- **当** 课程有多个有余量教学分组
- **则** 打开课程详情抽屉，学生选择教学分组后点击 footer「立即选课」加入选课篮

#### 场景：课程详情 section 布局

- **当** 学生打开课程详情
- **则** 以三段 section 展示：基本信息、教学分组、修读说明（含先修课）
- **且** 详情内不展示「你是否可选」资格区块
- **且** footer 提供「立即选课」主操作按钮

---

### 需求：学生端教学分组排课字段（Phase 21）

系统必须在学生选课相关界面展示教学分组的任课教师、起止周、上课时间、上课地点，并对易混淆字段提供说明。

#### 场景：教学分组卡片四字段

- **当** 学生在课程详情选择教学分组
- **则** 每个教学分组卡片展示任课教师、起止周、上课时间、上课地点
- **且** 起止周与上课时间旁提供 ⓘ 字段说明（区分开课周与课时周）

#### 场景：选课结果与课表同步

- **当** 学生查看选课篮、我的课表清单或我的选课结果
- **则** 同步展示上述排课四字段（主在线选课课程列表不增加四列）

---

### 需求：术语「教学分组 / Group」（Phase 22）

系统必须在选课模块对外文案中使用「教学分组」，不得使用「班级 / 教学班」产品用语；英文对应展示为 Group。

#### 场景：中文用语

- **当** 用户以中文查看选课管理端或学生端
- **则** 开课单元显示为「教学分组」，编号显示为「分组编号」
- **且** 提示、Tab、列表列名、流程说明中同类用语一并一致

#### 场景：英文用语

- **当** 用户以英文查看选课模块
- **则** 对应展示为 Group / Groups / Group No.（不再使用 Section 指代该实体）

---

### 需求：学生端加退课申请体验（Phase 23）

系统必须在学生加退课/重修页提供发起入口、规则说明与申请列表，并通过弹框提交少量字段的申请。

#### 场景：简化工具栏

- **当** 学生打开加退课/重修页
- **则** 不展示选课轮次时间轴
- **且** 工具栏仅展示批次名称与「发起申请」，不展示 Add/Drop 窗口 / 已选学分 / 待审批拼接描述

#### 场景：申请课程列

- **当** 学生查看「我的申请记录」
- **则** 表格提供「申请课程」列并展示课号
- **且** 申请类型单独成列，课程列不重复拼接类型名

#### 场景：说明与操作区分

- **当** 学生查看页内或弹框内说明
- **则** 说明以带底色提示块展示，与表单操作区区分
- **且** 弹框取消/提交按钮具备标准底色样式

#### 场景：弹框发起申请

- **当** 学生点击「发起申请」
- **则** 打开弹框填写操作类型与课程
- **当** 提交成功
- **则** 关闭弹框并刷新申请列表

---

### 需求：候补与选课结果去统计卡（Phase 24）

系统必须在学生「我的候补」「我的选课结果」页以列表与说明为主，不展示顶部统计卡片组。

#### 场景：候补页无统计卡

- **当** 学生打开我的候补
- **则** 不展示候补条数 / 待审批 / 可申请数等统计卡片
- **且** 直接展示说明与候补相关列表

#### 场景：选课结果页无统计卡

- **当** 学生打开我的选课结果
- **则** 不展示学分 / 门数 / 状态 / 批次等统计卡片
- **且** 直接展示说明、操作与已选课程列表

---

### 需求：我的候补只读（Phase 25）

系统必须将学生申请候补操作集中在在线选课，我的候补页仅供查看当前学生的候补记录。

#### 场景：在线选课申请候补

- **当** 学生在在线选课对满员课程申请候补
- **则** 写入候补队列（demo）

#### 场景：我的候补只读查询

- **当** 学生打开我的候补
- **则** 仅展示该学生的候补课程、顺位与状态
- **且** 不展示可申请课程列表与申请操作
- **且** 不展示选课轮次时间轴

### 需求：在线选课 demo 情况覆盖（Phase 26）

系统演示数据必须覆盖在线选课列表的主要情况，且已满且符合先修的候补候选靠前展示。

#### 场景：候补候选置顶

- **当** 学生打开在线选课课程列表（demo）
- **则** 已满且可选的课程优先于有余量可选课程展示
- **且** 对此类课程可发起申请候补

#### 场景：情况样例齐全

- **当** 学生浏览在线选课 demo 列表
- **则** 至少各见：有余量可选、已满可选（候补）、已修、缺先修、专业或 Intake 限制、已满但不可选

### 需求：在线选课去统计卡（Phase 27）

系统必须在学生「在线选课」页以轮次时间轴与课程列表/选课篮为主，不展示顶部统计卡片组。

#### 场景：无顶部统计卡

- **当** 学生打开在线选课
- **则** 不展示当前轮次 / 学分环 / 选课篮数量 / 可选门数等统计卡片
- **且** 仍可通过轮次时间轴切换轮次，通过选课篮查看学分进度

### 需求：我的课表去统计卡（Phase 28）

系统必须在学生「我的课表」页以周课表与已选清单为主，不展示顶部统计卡片组。

#### 场景：课表页无统计卡

- **当** 学生打开我的课表
- **则** 不展示轮次 / 学分环 / 门数 / 学期等统计卡片
- **且** 直接展示说明、周课表与已选课程列表

### 需求：弹框提示与课表轮次条精简（Phase 29）

#### 场景：加退课弹框无内嵌规则提示

- **当** 学生打开加退课发起申请弹框
- **则** 弹框内不展示规则 callout 提示块
- **且** 仍以操作类型与课程字段提交申请

#### 场景：课表页无轮次条

- **当** 学生打开我的课表
- **则** 不展示 Pre/Main/Supp/AddDrop 四轮时间轴卡片
- **且** 不展示批次名 + 课表说明行，直接进入周课表与已选课程列表

### 需求：详情 / 选课 / 候补职责拆分（Phase 30）

#### 场景：详情只读

- **当** 学生打开在线选课课程详情
- **则** 可查看基本信息与教学分组（只读卡片，无选中态）
- **且** 详情 footer 不含立即选课入口

#### 场景：立即选课独立选组

- **当** 学生点击立即选课（含仅 1 个有余量分组）
- **则** 打开独立教学分组选择弹框
- **且** 选组后加入选课篮，确认提交后完成注册

#### 场景：候补进篮后提交

- **当** 学生点击申请候补
- **则** 不弹教学分组选择，课程级加入选课篮并展示预计候补位
- **且** 确认提交后写入候补队列（任意教学分组待分配），不立刻入队

### 需求：批次与可选课程融合（Phase 19）

系统必须将可选课程配置并入选课批次页，不再提供独立「可选课程」侧边栏菜单。

#### 场景：管理课程抽屉

- **当** AC 在批次列表点击「管理课程」或课程数
- **则** 打开宽抽屉，标题明示为该批次管理课程，并列出本批已有课程

#### 场景：课程库多选导入

- **当** AC 在课程管理抽屉点击「从课程库导入」
- **则** 以多选表格选择器浏览课程库；本批已有课程置灰不可选
- **当** 确认导入
- **则** 选中课程加入当前批次

#### 场景：旧菜单兼容

- **当** 用户访问已移除的 `cr-courses` 页面 id
- **则** 重定向至选课批次页 `cr-batch`
