## 新增需求

### 需求：学生加退课申请

系统 MUST 提供与当前代码一致的「学生加退课申请」能力。

#### 场景：提交或编辑申请

- **当** 用户打开本菜单
- **则** 界面与数据符合现行实现

### 需求：退课学分摘要红字

退课选课弹窗在已勾选课程时，MUST 以红色展示学分摘要，文案 MUST 为「已选择 {n} 门课程，退课前学分为{a}分，退课学分合计{b}分，还剩学分为{c}分」。其中 **a** MUST 等于当前可退池全部课程学分总和（与表内可勾选课程学分列之和一致，含确认课与已批准申请注入的可退课），**b** MUST 等于已勾选行学分合计，**c** MUST 为 max(0, a−b)。**a MUST NOT** 取自学分条学期已选基线（GE+ME+必修）。申请表退课「选择」按钮旁 MUST 展示同等摘要：无退课行时灰色「未选择课程」，有退课行时红色摘要且 a/b/c 口径与弹窗一致。

#### 场景：弹窗勾选退课后

- **当** 学生在退课选课弹窗勾选课程
- **则** 摘要为红字且含退课前 / 退课合计 / 还剩；退课前为可退池学分总和

#### 场景：退课弹窗全选可退课

- **当** 学生全选可退池全部课程
- **则** 退课前学分等于退课学分合计，且等于表内各行学分之和；还剩为 0

#### 场景：申请表已选退课

- **当** 退课明细有行
- **则** 「选择」旁显示红色学分摘要（退课前仍为可退池总和）；无行时显示灰色「未选择课程」

### 需求：申请课程表序号与重修区布局

申请表与详情中退课、加课、重修课程表 MUST 在第一列展示序号；表格 MUST 不出现左右滑动。有重修区时，费用预估 MUST 位于重修补充说明之上。详情 SECTION IV 重修表 MUST 在「曾修课程」与「曾修课程成绩」之间展示同课号/同课程组重修列。

#### 场景：填写或查看申请课程

- **当** 打开申请表或详情且存在退/加/重修行
- **则** 各表首列为从 1 起的序号，且表体无需横滑即可读完主要列

#### 场景：查看重修公共区顺序

- **当** 申请表展示重修公共区
- **则** 先费用预估、后重修补充说明

#### 场景：详情重修明细

- **当** 详情展示 SECTION IV 重修表
- **则** 曾修课程列后为同课号重修（或同课程组重修）列，再为曾修课程成绩

### 需求：申请学分要求跨类别 Tab 一致

申请表顶部学分要求与重修选课弹窗学分要求 MUST 为同一套全局投影（基线 ⊕ 拟退 ⊕ 拟加 ⊕ 全部拟重修）。从必修/GE/ME 不及格原课任一入口打开重修选课器时，MUST 保留其它类别已选重修对学分条的贡献，不得只按当前原课池勾选重算。

#### 场景：跨 Tab 已选重修后打开另一原课选课器

- **当** 学生已在必修 Tab 选定重修，再从公共选修原课打开选课器
- **则** 弹窗学分要求仍计入已选必修重修，并随本窗勾选动态增减

### 需求：学生详情与审批审结学分/费用同源

学生端申请详情的学分要求与费用预估 MUST 与审批端同一申请在对应环节的投影一致：待审展示申请全量；审结后仅反映通过行（部分通过时不含不通过/驳回课的学分与费用）。

#### 场景：部分通过后学生打开详情

- **当** 申请已部分通过
- **则** 学分要求与费用明细与审批历史详情一致，不计入未通过课

### 需求：课程缴费整单与审批预估一致

学生「课程缴费」中某一申请整单的课程列表与合计 MUST 与该申请审批后的预估费用（`feeEstimate` 应付课）一致。

#### 场景：打开含部分通过重修的待缴整单

- **当** 预估仅含三门重修应付合计 5000
- **则** 该申请待缴整单仅该三门，合计与预估一致

### 需求：申请列表账单列

学生加退课申请主表 MUST 在「状态」后展示「账单」列，取值与文案 MUST 与审批历史账单列一致（待付款 / 已付款 / 已取消 / —）。

#### 场景：已通过待付款申请

- **当** 申请状态为已通过且 billStatus 为 pending
- **则** 状态后一列显示待付款

### 需求：二次申请须结清待缴

发起下一次申请前：若存在真实提交的未审申请 MUST 不可发起；若存在已通过或部分通过且账单待付款（有应付）MUST 不可发起，须先完成课程缴费；无应付或已付款后 MUST 可发起。二次打开申请表时学分要求 MUST 为上一单落地后的基线（有应付则缴完落课后）。

#### 场景：部分通过待缴未付

- **当** 上一单部分通过且待付款
- **则** 「发起申请」不可用，并提示需先缴费

#### 场景：无应付已通过

- **当** 上一单已通过且无应付账单
- **则** 可立即发起下一次，学分条含该单已落课结果

#### 场景：仅有 demo 种子待缴/待审

- **当** 列表仅有非 `adr-stu-` 的演示行（含待付款）
- **则** MUST NOT 因此禁用「发起申请」；第一次从学生新提交起算

### 需求：二次申请开窗提示与学分一致

窗口期内点击「发起申请」MUST 可打开申请窗。若存在真实未审单或真实待缴单，窗内 MUST 提示原因且 MUST 禁用表单操作与提交。学生已缴费（或无应付审结/拒绝）后，二次申请顶栏学分要求 MUST 与该生课表确认态一致，且与已落课审结详情的学分要求一致。

#### 场景：待缴时点发起申请

- **当** 有 `adr-stu-` 待缴账单
- **则** 申请窗打开，显示待缴提示，不可选课/提交

#### 场景：缴费后二次打开与详情

- **当** 上一真实单已付款落课
- **则** 二次申请顶栏学分与该单详情学分条数字一致（均为缴费后课表态）

### 需求：重修选课器一门原课仅一门开课

不及格重修与提分重修从原课表「选择重修课程」打开选课器时，MUST 使用单选（radio），MUST NOT 使用多选勾选框，表头 MUST NOT 提供一键全选。针对当前原课 MUST 最多选择一门符合条件的开课；选中后可将其余课程置灰。MUST NOT 像加课一样在同组或跨组多选多门。取消选中后 MUST 恢复其它行可选。多门不及格原课仍可分别各选一门写入同一申请（外层按原课一行一开课）。

#### 场景：重修选课为单选

- **当** 学生从原课行打开重修选课器
- **则** 行选择控件为 radio，无表头全选；radio 与行垂直对齐，点击 radio 即可选中（MUST NOT 需点偏下方）；确认后本原课仅对应一门开课

#### 场景：选中一门后其它组置灰

- **当** 学生在重修弹窗选中某课某分组
- **则** 其它课号及同课其它分组均不可选（置灰）

#### 场景：提分与不及格一致

- **当** 重修类型为提分或不及格
- **则** 均强制本窗单课（radio）

### 需求：我的课表仅审结生效后更新

列表工具栏「我的课表」MUST 展示申请前真实已选课表（`listMyResultCourses` / 已 schedule-effective 的审结结果），MUST NOT 因当前表单拟加/拟退/拟重修或未审、待缴申请而增删格子。申请弹窗内「课程预览」仍可对本单做假设投影。有应付时 MUST 在缴费成功落课后再更新「我的课表」；无应付时审批通过即可落课更新。

#### 场景：待审或待缴时打开我的课表

- **当** 学生已提交加退/重修申请但仍待审批，或已通过仍待缴费
- **则** 「我的课表」与提交前一致，不出现本单拟加/拟退/拟重修投影

#### 场景：缴费或无应付审结后

- **当** 申请已 schedule-effective（已付款落课，或无应付审结落课）
- **则** 「我的课表」反映落课后的已选课

#### 场景：默认落课时段无互撞（demo）

- **当** 演示生打开列表「我的课表」（未叠加本单拟加退重修）
- **则** 格子时段 MUST NOT 互撞；冲突通过统一调整上课时间消除，MUST NOT 以删除其中一门落课课为默认手段（选课器故意冲突样例除外）

#### 场景：我的课表抽屉无长说明

- **当** 学生打开「我的课表」抽屉（含加退课列表工具栏，以及「我的课程」页课表预览）
- **则** header 仅标题与学号姓名，MUST NOT 在学号下展示「含已选课（必修 / 选修 / …）」或「含选修课、必修课等有上课时间的课程…」类长说明

#### 场景：部分通过落课亦不互撞

- **当** demo 存在 PartiallyApproved 且通过行已 schedule-effective（如 STAT201 加课）
- **则** 该行时段仍 MUST 与确认半池/其它落课错开，MUST NOT 与 CYS201 等已选课同占一时段

### 需求：学分要求条一级二级配色

学分要求条 MUST：表头与默认数值为黑色、不随底色改字色。GE/ME/必修为一级——未满灰底；选满时底色与表头不变，仅「已选/要求」数值为绿色；超出时仅数值为红色。选修合计与已选总计（第3、5列）为二级——学期行与毕业行 MUST 均使用橙色底。申请表、选课器、详情、审批等共用该条组件的入口 MUST 表现一致。

#### 场景：学期 GE 选满且 ME 未满

- **当** 学期 GE 为 6/6、ME 为 14/22
- **则** GE 表头黑、底非绿，数值 `6/6` 为绿；ME 灰底黑字；选修合计与学期总为橙底黑字

#### 场景：毕业行二级亦为橙

- **当** 展示毕业行选修合计与毕业已选总
- **则** 该两格为橙底黑字（与学期二级一致，不用蓝底）

### 需求：退课选课弹窗选修退课提示

退课选课弹窗在「未选择课程」或已选摘要文案旁 MUST 展示可悬停/聚焦的 ? tip，说明：选课开放期间选修课应在选课页直接退课、不走申请，选修选项应置灰可看不可选；过了选课时间才可申请退选修。本阶段 MUST NOT 因此禁选或置灰选修行；demo MUST 仍允许勾选选修（视为已过选课时间）。

#### 场景：打开退课选课弹窗

- **当** 学生打开退课「选择课程」弹窗
- **则** 「未选择课程」旁可见 ?，悬停可见上述说明

### 需求：学分情况 tip 为截止到当前学期落下

学分要求条下方情况说明 MUST 以 programme study plan 起句，描述 MUST 为截止到当前学期的落下未修（进度落后），MUST NOT 表述为毕业整体还剩多少未修。各类别（必修/GE/ME）MUST 列出学分；无落下时该类别 MUST 为 0。Demo MUST 将落下控制为约必修 4、GE 4、ME 3。各共用该条组件的入口 MUST 一致。

#### 场景：有落下

- **当** 截止到当前学期存在落下未修
- **则** 提示形如「根据programme study plan，截止到当前学期落下未修学分为：必修课：…；GE：…，ME：…」

#### 场景：无落下

- **当** 各类别落下均为 0
- **则** 仍展示同一句式，对应学分为 0

#### 场景：拟退/拟加后 tip 动态

- **当** 退课选课器勾选退掉一门 GE（或加课勾选加一门 GE）
- **则** 蓝底 tip 中 GE 落下学分 MUST 随学分条投影增大（退）或减小（加）；ME/必修同理；MUST NOT 固定为打开弹窗时的静态培养方案剩余

### 需求：GE/ME 加课重修可选上限含因修未修

加课与重修选课器对 GE/ME：可选上限 MUST 为「因修未修固定 base（含拟退不含本窗拟加）+ 本学期该类学分要求」；拟加后学期已选超过该合计 MUST 置灰不可选。超限提示 MUST 说明已超过因修未修与本学期学分的合计上限，并带出合计值（可附因修未修与学期分项）。本学期要求为 0 但因修未修大于 0 时，MUST 仍允许在因修未修额度内选择。

#### 场景：无学期配额仅有落下

- **当** 本学期 GE 要求为 0、因修未修 GE 为 4、拟加后 GE 学期已选为 3
- **则** 可选；拟加后将达 5 时不可选并提示合计上限 4

### 需求：学分要求二维表

加退课/重修学分要求 MUST 以二维表展示，申请表、选课器、详情、审批同源。列 MUST 为：必修课、公共选修课、专业选修课、选修课合计、总合计。行 MUST 为：学期（表头两行「学期」「已选/要求」）、毕业（「毕业」「已选/要求」）、未修/因修。学期与毕业格数值 MUST 为 `已选/要求`，分母仅为对应学期或毕业要求，MUST NOT 在格内再写因修未修括号。选修课合计 MUST 为公共选修+专业选修；总合计 MUST 为必修+选修课合计。未修行数值 MUST 为 `未修/因修`：未修为随本单拟加/拟退/重修投影后的当前落下，因修为该类 live 学期已选（已修）+未修。必修/公选/专选列 MUST 保持一级灰底，选满仅数值绿、超出仅数值红；选修课合计与总合计列 MUST 保持二级橙底。表格 MUST 一页展示且 MUST NOT 横向滚动。蓝底落下 tip MUST 仍保留，且 tip 数值 MUST 为截止到当前学期的基线固定落下，MUST NOT 与矩阵未修行强制同源随勾选变化。

#### 场景：学期格不含因修括号

- **当** 必修学期已选 9、学期要求 9、未修 4
- **则** 学期必修格为 `9/9`；未修/因修必修格为 `4/13`

#### 场景：选修课合计与总合计

- **当** 学期 GE 6/6、ME 11/22、必修 9/9
- **则** 学期选修课合计为 `17/28`，学期总合计为 `26/37`

#### 场景：毕业行补分母

- **当** 毕业必修已选 9、毕业必修要求 72
- **则** 毕业必修格为 `9/72`，不得只展示 `9`

#### 场景：矩阵列与数值可见

- **当** 学分要求条已加载且 strip 有数据
- **则** 列表头（必修课/公共选修课/专业选修课/选修课合计/总合计）与各格数值 MUST 可见；容器 MUST NOT 套用会把整表挤进单列的 R1 五列 Grid（`cr-r1-credit-panel`）

### 需求：申请弹窗课程预览

加退课/重修申请弹窗 MUST 提供「课程预览」按钮，位置 MUST 在申请弹窗底栏左侧，与「取消」「提交申请」同一行（预览在左，取消/提交在右）；MUST NOT 再放在说明 callout 右上。预览 MUST 仅根据**当前表单**填写的加课、退课、重修即时投影，MUST NOT 展示上一张申请的操作结果。当本单尚未勾选任何加/退/重修课程时，预览格子 MUST 与外面「我的课表」展示的已选课程一致（申请前真实课表）。有勾选时预览 MUST 为**拟退生效后**的课表：保留课实线必修/选修色 + 加课申请虚线 + 重修申请虚线；MUST NOT 再绘制退课课程内容或退课虚线框。剔除拟退的键 MUST 与选课冲突基线同源（`pendingDropCodes` / 拟退课号与课 id）。无上课时间的课程 MUST NOT 进入课表格。

预览抽屉打开时 MUST 盖过申请弹窗（层级高于申请弹窗）。抽屉 header MUST 仅含标题「课程预览」与学号姓名，MUST NOT 在标题中带「（本单参考）」等括号副标，MUST NOT 在学号下再挂长说明，MUST NOT 展示浅蓝 tip。内容区置顶为：四项图例 → 课表格。图例 MUST 为必修课、选修课、加课申请（虚线）、重修申请（虚线），MUST NOT 含「退课申请」图例项。加课申请虚线色 MUST 为绿色，重修申请虚线色 MUST 为橙色，且在必修底色与选修底色上均 MUST 可见虚线边框。抽屉 footer MUST 在左侧以提示条样式展示「课程预览仅为此次申请操作的预期结果，真实课程安排以审批结果为准」（含「提示」徽章、浅蓝底框、文案加粗），右侧为关闭按钮；MUST NOT 把该提示放回内容区 tip，MUST NOT 仅用弱对比灰字。当投影无任何课块时，MUST 仍展示图例与周一至日时间轴空表，MUST NOT 仅用「暂无课表安排」整页占位而隐去时间轴。加课与重修彼此之间（含表单同侧已确认行）、以及与保留课（含保留必修）之间 MUST NOT 存在可选中的时间冲突：选课弹窗 MUST 硬拦；预览 SHOULD NOT 因漏拦而出现可提交的互撞重修/加课对。

#### 场景：无申请勾选时同我的课表

- **当** 表单加课、退课、重修行均为空
- **则** 课程预览格与当前「我的课表」一致；图例仍为五项申请图例

#### 场景：随勾选即时变

- **当** 学生在表单勾选一门加课
- **则** 再打开或保持打开的预览 MUST 出现该加课虚线格，MUST NOT 依赖提交后再开新申请才看到

#### 场景：无 tip 且图例四项

- **当** 学生打开课程预览抽屉
- **则** 标题为「课程预览」；无浅蓝 tip；图例为必修/选修/加课申请（虚线）/重修申请（虚线），不含退课申请

#### 场景：预览盖过申请弹窗

- **当** 申请弹窗已打开且学生点击「课程预览」
- **则** 预览抽屉完整可见，不被申请弹窗遮挡

#### 场景：拟加虚线分色

- **当** 学生勾选一门加课且该课有上课时间

### 需求：本单拟退对齐加课池原组

### 需求：学生申请列表四态与草稿

学生端加退课/重修申请列表状态 MUST 展示为四态：**草稿**、**待审批**、**已驳回**、**已结束**。映射规则：`Draft`→草稿；`Pending`/`In Review`→待审批；**以全部课程行操作为准**——任一行决策为驳回（`update_required`）→已驳回；终态且行决策仅为通过（`approved`）与/或不通过（`rejected`）、无驳回行→已结束（含全部通过、部分不通过、全部不通过）。筛选 MUST 按四态；草稿行 MUST 提供「编辑」回填申请表；草稿 MUST NOT 计入未审二次申请门控。学生详情与老师详情中的状态徽章 MUST 与列表四态文案一致。老师历史 Tab MUST 使用同一套终态映射，并额外展示 **已取消**（含学生取消与老师中止的 `Cancelled`）。老师审批确认 MUST 允许同一单内混选通过/不通过/驳回；有驳回行时整单变为已驳回并写回各行决策。

申请弹窗点「取消」时：MUST 与打开窗口时的表单快照比较；**仅当有改动**才提示是否存入草稿；**无改动 MUST 直接关窗不提示**。确认存草稿则保存并关窗；否认则丢弃关窗。

已驳回申请 MUST 提供「重新提交」：打开弹窗展示本单加课/退课/重修行及行审批结果（布局对标老师审批弹窗行表）。行决策为已通过或不通过的课程 MUST 只读不可改；行决策为驳回（`update_required`）、已换课待审批（`pending`+已改）、或已取消（`cancelled`）的课程 MUST 提供「修改」（换课）与「取消申请」。点击「取消申请」MUST 先确认弹框；确认后该行决策 MUST 变为 `cancelled`（展示「已取消」），MUST NOT 从工作表删行。已取消行在整单确认重新提交前 MUST 仍可「修改」；换课成功后决策 MUST 变为 `pending`（待审批）。MUST NOT 在重提中新增课程行。点「确认重新提交」MUST 至少保留一条非已取消行即可点——学生 MAY 对部分驳回行不修改也不取消，工作行仍为 `update_required`（已驳回）；MUST NOT 因仍有驳回行而置灰确认按钮；MUST NOT 再在底栏展示「请先将全部驳回课程修改为待审批…」红字说明。可点后 MUST 先弹出确认框，学生确认后才提交；取消则留在重提窗。确认提交时 MUST 以弹窗内**非已取消**的全部最新数据行整单重新提交为待审批：已通过/不通过行 MUST 保留其行决策与评价意见；学生已换课的原驳回行 MUST 以最新课数据进入待审（`pending`）并保留原评价意见；**未修改也未取消的驳回行 MUST 仍写回 `update_required`（已驳回）并保留评价意见**，老师再审 MUST 仍见「已驳回」且默认锁定不可改；`cancelled` 行 MUST NOT 写入本单。若学生取消全部驳回行后仅剩已通过/不通过行，仍 MUST 允许提交为待审批；老师 MUST 再次打开审批并点确定后，整单才变为已结束。demo 中展示为已驳回的申请 MUST 至少含一条 `update_required` 行。

重新提交弹窗课程表下方 MUST 展示 SECTION「附件材料」（选填），学生可增删附件；确认重新提交 MUST 将当前附件写回本单。无附件时仍展示该节。

加课驳回换课打开选课器时，MUST 仅展示该驳回行所属课程类别（必修 / 公共选修 / 专业选修之一），MUST NOT 同时展示多个类别 Tab；类别锁定口径 MUST 与行展示课性一致（统一课性 / `required`→core），MUST NOT 将 `MANDATORY` 误判为 ME。退课换课 MUST NOT 出现类别 Tab；重修换课继续按原课类别锁定，且列表 MUST 仅含该课性课程（GE 修改 MUST NOT 出现必修或 ME；ME 修改 MUST NOT 出现 GE 或必修）。有类别锁定时过滤 MUST 生效，与是否展示 Tab 无关。ME/GE/必修重提选课的候选过滤与置灰规则（课程分组、组内已选、课程组替代/minPick、课表冲突、学分帽）MUST 与正式加课申请同源。

退课/加课驳回换课选课池中，本单其它行已占用的同课号 MUST 置灰只展示不可选（含已通过/不通过/其它驳回或已换课行）；MUST NOT 因「已通过」而把无关候选课整表置灰。重修驳回换课继续按同类型已通过/不通过占用置灰。选课器中可选课 MUST 可点选；已选原课 MUST 允许再点取消勾选；不可选行 MUST 置灰并展示原因。选课器点「确认」MUST 写回重提工作行；换课成功后该行决策 MUST 变为 `pending`，行上展示「待审批」，并保留原评价意见；整单「确认重新提交」之前，该行 MUST 仍可「修改」「取消申请」。重修驳回换课打开选课器时，即使预勾旧课，其它合适课程 MUST 仍可选（单选点换），MUST NOT 以「该课程已选择其他课程」整表禁选。加课若触发超额确认弹层，其层级 MUST 高于选课器，MUST NOT 出现点击确认无反馈。

重新提交弹窗底栏左侧 MUST 提供「课程预览」。预览 MUST 与弹窗内当前课程内容一致：加课/重修虚线仅含已通过行，以及学生已「修改」换课后的原驳回行；未修改的驳回加/重修 MUST NOT 出现在预览；已取消申请的行 MUST NOT 出现。拟退仅对已通过退课或已换课的驳回退课生效。基线为「我的课表」实课表。

重新提交弹窗中：课程名称与课程类型 MUST 为课库合理取值（MUST NOT 用课程代码冒充名称，MUST NOT 因缺 `type` 长期显示「—」）；上课时间地点多段时 MUST 缩为单行摘要（首段 + `…`），完整内容可通过悬停查看；弹窗 MUST 在课程表上方展示学分要求条（对标审批弹窗 `AddDropTermCreditStrip`），并随当前工作行决策投影。

重新提交弹窗 MUST 适当加宽并对齐审批行表列序；MUST NOT 向学生展示「可选名额/总名额」；行上若有老师评价意见（`lineComment`）MUST 提供「意见详情」只读查看，MUST NOT 漏展示。重新提交弹窗学分要求（含蓝 tip）MUST 钉在滚动区上方（上钉下滚），课程表滚动时 MUST NOT 从学分条区域透出。老师审批弹窗行表表头（含序号、学分等）MUST 完整可见，MUST NOT 因列宽不足被 ellipsis 裁成缩写；可通过加宽短列或横向滚动满足。老师再次审批重提单时：MUST 回显上次通过/不通过/已驳回与意见及学生调整后的课数据；打开时行决策已是通过、不通过或仍为已驳回（`update_required`，学生未改）的行 MUST 置灰锁定（radio 与评价意见均不可改）；仅 `pending`（学生已换课的原驳回）及尚无历史终态决策的行可调整。首次全新待审（行尚无通过/不通过历史）仍可改全部。

选课器「课程组」列：真实课程组（如 Group2 + Intake）MUST 照常展示；非真实 Group 的虚拟大组（如 GE 全部可选、ME 未入 n 选 m）MUST 显示「—」，MUST NOT 展示「GE (全部可选 GE)」类描述。

学生「课程缴费」待收费整单 MUST 展示「生成时间」（`billGeneratedAt`），与「缴费截止」一并可见。已结束且有应付的申请 MUST 同步生成/对齐待缴账单（含 live reconcile）；**全部** demo 待缴/已缴行（含原有 seed 与 live merge）MUST 含非空 `billGeneratedAt`，hydrate 后缺失 MUST 补齐。

申请详情重修表「曾修课程成绩」列 MUST 单行展示（MUST NOT 换行拆字）；过长可 ellipsis 缩写，悬停 MUST 可看完整原文。

学分要求蓝底 tip MUST 表示截止到当前学期的历史落下（各类别还差多少学分），MUST NOT 随本单拟加/拟退/重修或行审批勾选而变化。蓝 tip MUST 另展示在线选课第三轮（`rounds.supplement`）配置起止，说明选修课加/退受该时间段约束（与加退课申请窗 `addDropWindow` 区分）；本增量仅展示，MUST NOT 因此硬禁选。矩阵第三行「未修/因修」MUST 随本单学分条投影（含拟加、拟退、重修）实时变化：未修按本学期已选与落下累计原则增减（例如本学期超出要求 1 学分则未修相应减少 1）；因修右项 MUST 为该类 live 学期已选 + 未修。学期/毕业「已选/要求」行仍可随投影变化。

重新提交换课：MUST NOT 新增行；驳回行可替换课程或取消删行；选课器 MUST 单选；MUST 按该行申请类型（退课/加课/重修）进入对应选课池并适用同类申请规则（含课表冲突、学期学分/GE·ME 因修未修上限、重修原课与重修类型）；MUST NOT 为打开选课器而改写主申请表单的 needDrop/needAdd/needRetake。重修驳回换课 MUST 带上原课焦点与申请重修类型。

- **则** 选课器候选分别来自在读可退、可加资格、重修池，MUST NOT 出现把退课课表原样当作加课/重修池的情况

#### 场景：重提行决策彩色胶囊

- **当** 学生打开已驳回「重新提交」弹窗
- **则** 行操作决策列以彩色胶囊展示通过/不通过/驳回，样式对标申请详情

#### 场景：占用锁仅同申请类型

- **当** 本单有已通过的退课行占用 ENGL201，学生修改驳回的重修行打开重修选课器
- **则** ENGL201 MUST NOT 仅因该退课已同意而被置灰；仅当另有已通过/不通过的**重修**行占用同一课时才置灰

#### 场景：重修驳回可换其它可选课

- **当** 学生修改驳回的重修行打开选课器
- **则** 可在同重修类型池内选择其它仍可选课程（非强制仅原课教学班），仍受及格/冲突/学分等规则约束

#### 场景：有驳回行展示为已驳回

- **当** 审批结果中至少一行操作为驳回（可与通过/不通过并存）
- **则** 学生列表与详情状态徽章展示「已驳回」，MUST NOT 展示「已结束」

#### 场景：仅通过与不通过展示为已结束

- **当** 审批结果行操作仅为通过与/或不通过（无驳回行），含部分不通过或全部不通过
- **则** 学生列表与详情状态展示「已结束」，MUST NOT 展示「已驳回」，且 MUST NOT 提供「重新提交」

#### 场景：全部同意展示为已结束

- **当** 申请全部课程行同意
- **则** 学生列表与详情状态展示「已结束」

#### 场景：无改动取消不提示草稿

- **当** 学生打开申请窗后未做任何修改即点取消
- **则** 直接关窗，MUST NOT 弹出存草稿确认

#### 场景：取消存草稿并可编辑

- **当** 学生填写了加/退/重修内容后点取消并确认存草稿
- **则** 列表出现草稿行且可点「编辑」继续填写；提交后变为待审批

#### 场景：已驳回换课整单重提

- **当** 学生在已驳回申请上点重新提交，仅修改驳回行的课程后确认
- **则** 该申请以含已通过/不通过行与已换课行的全部最新 items 回到待审批

### 需求：修读方式全文与已驳回禁发起

申请表与详情中重修汇总「修读方式」列 MUST 全文展示「同课号重修」或「同课程组重修」，MUST NOT 以 ellipsis 缩写。存在学生真实提交且展示为「已驳回」的申请时，MUST 禁止「发起申请」新单（窗内提示与待审二次门控同类），仍允许对该单「重新提交」。详情操作列行决策 MUST 以彩色胶囊展示通过/不通过/驳回。

#### 场景：已驳回不可再发起新申请

- **当** 学生列表存在展示为已驳回的真实提交申请
- **则** 打开「发起申请」后表单操作禁用并提示须用「重新提交」；列表「重新提交」仍可用

### 需求：重修灰字移除与二次申请合并红字

申请重修区 MUST NOT 再展示「汇总必修/公选/专选…合计」类灰字提示。有未审申请拦截二次提交时，红字提示 MUST 合并「学分课程为估算、须审批确认」与「待审不可再交、取消后可再发起」两层含义，前缀感叹号；蓝底学分 tip 内 MUST NOT 再单独展示原估算说明句。详情课程表「任课教师」列 MUST 尽量完整展示、减少省略号缩写。

### 需求：退课池与我的课表同源

退课选课池 MUST 与「我的课表」/课程预览/加课冲突基线使用同一已选集合：`listMyResultCourses`（必修底图 ∪ 确认课 ∪ 已批准申请加课/重修）。MUST NOT 仅用确认半池选修而遗漏申请来源课，导致「退课学分已清零但预览/加课仍被申请课占用」。未审底账已拟退的课 MUST NOT 再出现在退课池。

#### 场景：已批准申请课可退

- **当** 学生课表含已批准申请写入的加课或重修（如 COMP3192 / STAT201 / MATH201），且不在未审拟退底账中
- **则** 退课选课池 MUST 列出该课；勾选拟退后，课程预览与加课冲突基线 MUST 同步剔除该课

#### 场景：全退后仍见时间轴

- **当** 拟退生效后预览无任何课块
- **则** 仍可见四项图例与周时间轴空表，不得整页仅「暂无课表安排」

#### 场景：二次重修与已确认重修互撞拦截

- **当** 表单已有一门重修，学生再次打开重修选课勾选与其时段重叠的另一门
- **则** 该行 MUST 因时间冲突不可选；MUST NOT 仅靠课程预览打 ! 暴露问题

#### 场景：拟退腾出后加课不假冲突

- **当** 学生拟退一门课并在同（或重叠）时段勾选一门加课或重修，且选课弹窗允许勾选
- **则** 课程预览 MUST NOT 因已拟退课程显示冲突；冲突仅在保留课、加课申请、重修申请之间判定

### 需求：退课学分字段标签含「（分）」

申请表单展示退课学分汇总的三个只读字段标签 MUST 带「（分）」后缀：退课必修课（分）、退课专业选修（分）、退课公共选修（分）。

#### 场景：退课学分三字段

- **当** 表单展示退课学分汇总
- **则** 三字段标签分别为退课必修课（分）、退课专业选修（分）、退课公共选修（分）

### 需求：加课 ME Tab 并存孤立课与未完成课程组

加课「专业选修」Tab MUST 同时展示：资格池中的孤立 ME 课，以及培养方案/批次中未完成 minPick 的课程组。对「已选门数少于 minPick」的组（如 3 选 2 已选 1 门）：MUST 展示组内已选课并置灰不可勾选，MUST 展示其余未选可修课供选择。已完成 minPick 的组 MUST NOT 再展开为加课组视图。

#### 场景：3选2 已选一门

- **当** 组内三门课已确认一门、minPick 为 2
- **则** ME Tab 可见该组：已选课置灰，另两门可选；同 Tab 仍可见其它孤立 ME

#### 场景：课程组列合并展示

- **当** 加课 ME Tab 存在真实 n 选 m 课程组
- **则** 同组各课各分组行连排；「课程组」列对本组多行 rowspan 合并（对齐在线选课 ME）；MUST NOT 因上课学期排序或分页将同组拆散为互不接邻的独立课块

#### 场景：孤立 ME 课程组列为单一破折号

- **当** 加课 ME 课不在 n 选 m 组内且有多个课程分组行
- **则** 「课程组」列 MUST 按课合并为一格并显示「—」，MUST NOT 每个分组行各显示一个「—」

### 需求：重修曾修学期成绩为课级列

重修选课器「曾修学期/成绩」MUST 按课程合并（跨该课各课程分组行 rowspan），MUST NOT 按教学班分行。履历 MUST 取该课级曾修记录；有成绩时 MUST NOT 再展示「—」。该列 MUST 位于一级（课级）字段最后一列（在课程分组等二级字段之前）。

#### 场景：多分组同行曾修

- **当** 重修课有两个课程分组且课级有曾修成绩
- **则** 「曾修学期/成绩」仅一格跨两行，展示成绩文案且无「—」

### 需求：不及格原课 Tab 展示门数

重修申请表「不及格课程 / 可提升成绩课程」外层三 Tab（必修/公选/专选）标签 MUST 附带「（N门课程）」；N MUST 为当前重修类型池中该类别的课程门数，并随池数据变化。

#### 场景：有不及格必修

- **当** 不及格池含 2 门必修、0 门公选、1 门专选
- **则** Tab 文案为「必修课（2门课程）」「公共选修（0门课程）」「专业选修（1门课程）」

### 需求：加课 ME 课程组选满 minPick 后禁选其它课

加课选课器对真实课程组（含 3 选 2、4 选 3、2 选 1）：已确认与本窗已选门数达到 minPick 后，组内尚未选中的其它课程 MUST 置灰不可选，并提示组内已选满/只需再选的门数约束。同课其它分组仍按同课互斥。孤立 ME（无组）不受本规则影响。

#### 场景：3选2 已选一门后再选一门

- **当** 组内已确认 1 门、minPick 为 2，学生勾选剩余课之一
- **则** 组内另一门未选课置灰并提示不可再选

### 需求：学期超出学分扣因修未修

「学期超出学分」MUST 仅统计学分条 GE/ME 在扣减因修未修额度之后仍超过本学期要求的部分，即 max(0, 已选 − (学期要求 + 因修未修))。因修未修补上的学分 MUST NOT 计入超出。字段旁 MUST 有 tip：开了白名单允许超出学期学分的学生才展示该字段，否则不允许超出也不展示；Demo MUST 仍展示该字段以便验收。

#### 场景：GE 补落下不算超出

- **当** 学期 GE 要求 6、因修未修 GE 为 4、拟加后 GE 已选 9
- **则** 学期超出学分为 0（9 ≤ 6+4）

### 需求：加课必修换组锁区分早先学期与当前学期

加课/加退课选课器对必修换组：若该课「原上课学期」均早于当前申请学期，MUST 允许选择同课其他分组且 MUST NOT 要求换组白名单。若原上课学期为当前申请学期（本学期退再加或同学期原组），MUST 默认仅可选原课程分组；选择其他分组 MUST 依赖换组白名单（含 allow-all）。校验提交 MUST 与弹窗置灰规则一致。

#### 场景：早先学期曾退

- **当** 原上课学期为 2026/04 且申请学期为 2026/09
- **则** 同课其他分组可选，无需白名单

#### 场景：当前学期原组

- **当** 原上课学期为 2026/09、原组为 01、无换组白名单
- **则** 分组 02 置灰「不符合该分组选课要求」；01 可选

### 需求：整单附件材料节

申请表与详情 MUST 在「学生声明」前提供「附件材料」节，附件为整单共用（选填），MUST NOT 挂在退课专属区。申请表该节提供上传（格式/大小/数量限制与现行一致）。详情 MUST 始终展示该节：有附件列出文件，无附件显示无。审批弹窗与重新提交弹窗中的附件节标题 MUST 仅为「附件材料」，MUST NOT 带 `SECTION n :` 前缀；重提上传按钮/排版 MUST 对齐申请表。

#### 场景：申请表声明前有附件材料

- **当** 学生打开加退课/重修申请弹窗（无论是否勾选退课）
- **则** 费用预估与学生声明之间有「附件材料」小节，可上传选填附件

#### 场景：详情无附件仍展示节

- **当** 打开无附件的申请详情
- **则** 声明前仍有「附件材料」小节，内容为无

#### 场景：审批/重提附件标题无 SECTION 前缀

- **当** 打开审批弹窗或重新提交弹窗的附件节
- **则** 标题文案为「附件材料」，MUST NOT 出现 `SECTION V :` 等前缀

### 需求：详情行待审批文案

申请详情课程表中行决策为待审/`pending` 时，MUST 展示「待审批」，MUST NOT 展示「待定」。

#### 场景：详情 pending 为待审批

- **当** 打开含 `pending` 行的申请详情
- **则** 操作列胶囊文案为「待审批」

### 需求：课程缴费待缴已缴一致

学生课程缴费中，同一笔已支付订单在「已缴费」展示的课目与金额 MUST 与支付时一致。已缴费分组 MUST 优先按 `orderNo`；整单卡片「合计费用」MUST 与行上课程费口径一致（`feeTotal`/`feeAmount`）。从审批同步的待缴行 MUST 按行 id 去重，避免同课重复抬高合计。

#### 场景：缴费前后合计一致

- **当** 学生支付某申请整单后查看已缴费
- **则** 课门数与合计费用与待缴费/支付时该订单一致

### 需求：课程组内已选红色提示

加课选课器「可选名额/总名额」列中组内已占/选满提示（`groupMemberAlreadyTaken`）MUST 使用红色（conflict），文案 MUST 表达「组内已选满」含义（如「组内已选满」），MUST NOT 显示为可选绿色，MUST NOT 仅用含糊的「课程组内已选」。

#### 场景：组内已选满为红字

- **当** ME 课程组内某课已确认或已占，组内其它分组行不可再选
- **则** 展示「组内已选满」类红字，与「上课时间冲突，不可提交」同级提示色

### 需求：重提申请类型胶囊与附件样式

重新提交弹窗课程表「申请类型」列 MUST 以彩色胶囊区分加课/退课/重修（蓝/红/黄，与详情同源）。「选择文件」按钮 MUST 与申请表附件按钮同高、同色、文字居中。

#### 场景：三类申请类型胶囊

- **当** 重提表含加课、退课、重修行
- **则** 三类申请类型各为不同颜色胶囊，不得为纯黑字

### 需求：ME 重提仅同课程组

ME 加课/重修驳回「修改」打开选课器时，除课性锁定外 MUST 仅展示与原行相同课程组范围的候选：课程组列为「—」的普通 ME 仅普通池；属于真实 n 选 m Group（如 Group1）时 MUST 仅该组，MUST NOT 出现其它 Group 或普通「—」行。

#### 场景：普通 ME 修改不含几选几

- **当** 学生修改课程组为「—」的 ME 驳回行
- **则** 选课器 MUST NOT 出现 Group1/Group2 等几选几组课程

#### 场景：Group1 修改不含 Group2

- **当** 学生修改属于 Group1 的 ME 驳回行
- **则** 选课器 MUST 仅 Group1，MUST NOT 出现 Group2 或课程组「—」行

### 需求：重提有效拟退才腾时段

重提换课与确认重新提交的课表冲突基线 MUST 仅排除「有效拟退」：已通过退课，或已换课且计入预览的退课。退课「不通过」、未改的驳回退课、已取消退课 MUST NOT 从基线剔除对应课。加课/重修与仍在读课（含退课不通过仍保留的课）时段冲突时 MUST 拦截，选课器红字与确认提交均 MUST 生效。

#### 场景：退课不通过后加课撞时段被拦

- **当** 本单 BUS301 退课为不通过、COMP220 加课驳回后学生再次选择与 BUS301 冲突的分组并确认
- **则** 系统 MUST 拦截（选课确认或确认重新提交），MUST NOT 允许提交造成课表冲突

### 需求：操作列已驳回文案

详情与重新提交操作列中行决策 `update_required` MUST 展示「已驳回」，MUST NOT 展示单独「驳回」。

#### 场景：详情驳回胶囊

- **当** 打开含驳回行的申请详情或重提弹窗
- **则** 操作列胶囊文案为「已驳回」

### 需求：重修单选可取消与必修仅原课

重修（含重提）选课器单选模式下，已勾选行 MUST 允许再点取消勾选（即使该行因时段冲突等呈禁用态）；取消后可在限制允许条件下另选其它行。必修课重修重提修改时，候选 MUST 仅原课号各教学分组，MUST NOT 出现其它必修课数据行。

#### 场景：冲突预勾行可取消

- **当** 重提修改必修重修且预勾行显示时段冲突红字
- **则** 学生 MUST 能取消该勾选，再选其它允许分组（若有）

#### 场景：必修重修不出现其它课

- **当** 学生修改 MATH101 必修重修驳回行
- **则** 选课器 MUST 仅 MATH101 各分组，MUST NOT 出现 PHYS101 等其它课

### 需求：选课器横线与组内不可选细化

加课 ME 选课器数据表横线在课程组底色上 MUST 清晰可见。组内不可选文案 MUST 区分：该课已在本组选定；以及本组 n 选 m 门数已满。

#### 场景：组内两类原因不同文案

- **当** COMP201 已在组内选定、同组其它课因 minPick 已满不可选
- **则** 前者说明该课已选定，后者说明组门数已选满（含 n 选 m）

### 需求：待重提学分按行决策投影

已驳回待重新提交的申请：详情与重提主界面学分要求 MUST 按行决策同源投影——已通过计入；不通过、未改驳回、已取消不计；学生换课为 pending 后计入。同一重提弹窗内换课选课器在未整单提交前 MUST 与重提顶栏学分跟手，并随本窗勾选变化。

#### 场景：未改操作时详情与重提一致

- **当** 学生打开已驳回单的详情与重新提交且尚未修改任何行
- **则** 两处学分要求矩阵已选/要求一致

#### 场景：重提换课选课器跟手

- **当** 学生在重提中修改某行并在选课器勾选
- **则** 选课器顶栏学分与重提主界面投影规则一致，并反映当前勾选

### 需求：重提选课初始学分与确认反馈

重提换课选课器：MUST NOT 展示「退课前学分/还剩学分」红字摘要。刚打开且勾选仍为原驳回课时，学分要求 MUST 与重提主界面一致；学生改选后 MUST 在该基础上变化。确认校验失败 MUST 在选课器内提示，MUST NOT 仅静默。

#### 场景：置灰行不可新选（增量 bp）

- **当** 行因冲突/满员/组内已满等被置灰
- **则** 状态列在未选前已提示原因，且 MUST NOT 允许点选该行（修改场景下仅原预选行可取消勾选并可再勾回该预选行；其它置灰行仍不可选）

#### 场景：打开修改学分对齐外层

- **当** 学生点驳回「修改」进入选课器且尚未改勾选
- **则** 选课器学分矩阵与重提主界面一致

#### 场景：确认失败可见

- **当** 学生点确认但校验失败（冲突/学分等）
- **则** 选课器内出现错误提示，弹窗保持打开

### 需求：退课池与学分条同源（增量 bq）

演示生可退池学分与学分条学期已选 MUST 一致（基线 26）。历史审结中未并入确认半池/必修池的加/重修 MUST NOT 因已缴或无账而自动进入可退池。

#### 场景：打开退课选课器

- **当** 演示生打开退课选课器且未另拟退
- **则** 「退课前学分」与学分条总合计已选均为 26，可退列表仅为必修+确认半池课程
